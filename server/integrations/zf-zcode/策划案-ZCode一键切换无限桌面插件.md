# 策划案：ZCode 一键切换无限桌面（zf-infinite-desktop 插件）

> 版本 **v1.1** · 2026-10-24 · 定位：前台即产品，渠道即一切
> 用户拍板项（v1.0）：① 唤起独立窗口；② 引擎走 ZCode 自己的；③ ~~我们零流量零模型成本~~（成本归属已被 v1.1-② 取代：零流量仍成立，零模型成本已废弃，改为"售线路"模式）。
> 用户拍板项（v1.1）：① 呈现方式升级=pywebview 原生窗口去浏览器化；② 朱峰线路为默认引擎，我们管理线路、按朱峰 Token 计费。

---

## 一、目标

ZCode 用户安装一个插件 → 点「无限桌面」按钮 → 唤起原生独立窗口，直接进入朱峰无限桌面多窗口布局。
体验目标：**点一下按钮，界面就是我们的**，一步到位；ZCode 原窗口保留，可随时切回。
商业目标：借 ZCode 现有用户量做分发渠道 + **售朱峰模型线路**双收入。

## 二、核心架构（三个部件）

```
[ZCode 应用]
   └─ zf-infinite-desktop 插件
        ├─ ① 按钮/命令：「无限桌面」
        │     └─ 点击 → 检测/拉起本地服务 → pywebview 原生无边框窗口全屏渲染无限桌面 UI
        │        （兜底：目标机 WebView2 缺失时自动退回系统默认浏览器打开）
        ├─ ② 本地服务轻包（zf-bridge-lite）
        │     ├─ 静态托管无限桌面 UI（public/canvas/ 等前端资源，纯本地）
        │     ├─ 提供 UI 所需的最小 HTTP API（对话消息注入、画布事件）
        │     ├─ 出站转发：UI 发起的消息转给引擎（默认朱峰线路，可切 ZCode GLM）
        │     └─ 窗口壳：pywebview（Python + 系统 Edge WebView2），零 Node/Electron 依赖
        └─ ③ 无限桌面 UI（复用现有前端，零重写）
```

**成本归属（v1.1 硬约束，取代 v1.0 口径）**
- UI 静态资源：用户本地磁盘，**零流量**（此条不变）。
- 引擎/大模型：**默认朱峰线路**——用户登录朱峰账号，按朱峰 Token 计费；ZCode 自己的 GLM 线路保留为第二选项，可切换。
- 模型流量：用户**直连模型厂商**，不经我们服务器代理；朱峰远端只提供轻量鉴权/计费核对接口（验证账号 token + 下发可用线路列表），服务器压力极小。
- 安全约束：朱峰账号凭证只存本地加密，绝不下发明文 key；线路列表可远程开关（可控量）。

## 三、MVP 范围（P0，两周内可验）

**P0-1 插件壳 + 按钮**
- plugin.json + 命令注册「zf-infinite-desktop: 打开无限桌面」
- 点击逻辑：本地服务未启动 → 用 ZCode 可用的 Python 起服务；已启动 → 直接唤起
- 唤起方式（v1.1）：**pywebview 原生无边框窗口**全屏渲染无限桌面 UI，体感与朱峰智能体无限一致；WebView2 缺失时退回系统默认浏览器

**P0-2 zf-bridge-lite 本地服务**
- 复用现有 8570 服务思路但做**精简独立版**：只托管 UI + 对话注入 API + 窗口壳
- 依赖最小化：核心服务纯 Python 标准库单文件，**不依赖 fastmcp/朱峰完整项目目录**；窗口壳新增一个 pip 依赖 pywebview（有浏览器兜底，不堵死）
- 端口：动态选取，写 private/port.json 同款机制

**P0-3 引擎桥（关键可行性点）**
- UI 里的对话 → bridge → 转发给引擎执行通道
- 引擎双线路（v1.1）：默认朱峰线路（用户朱峰账号 token，本地加密存储，直连厂商），第二选项 ZCode GLM
- 候选通道（按优先级调研）：
  a. ZCode CLI headless 模式（若有，最干净）
  b. ZCode 插件 API 提供的消息发送接口
  c. 退路：MCP 反向——UI 只是"遥控器"，对话仍由用户在 ZCode 主窗发起
- P0 先做 c（退路兜底，保证任何情况下 UI 能显示状态），a/b 调研通过后升级

**P0-4 验收标准（v1.1 修订）**
1. 在 ZCode 安装插件 → 点按钮 → pywebview 原生窗口打开无限桌面 ≤ 5 秒（WebView2 缺失时退回浏览器打开同样计入达标）
2. 抓包/网络面板验证：UI 静态资源与 bridge 通信**零外网请求**；模型流量仅用户直连模型厂商（朱峰线路=直连朱峰 API，GLM 线路=直连智谱），不经我方代理服务器
3. bridge-lite 单文件可独立运行：拷到只装了系统 Python 的干净机器，pip install pywebview 后即可起服务（fastmcp 不在依赖里）
4. 同一台机器与朱峰主程序共存不冲突（端口错开、数据目录独立）
5. （v1.1 追加）默认朱峰线路下，登录朱峰账号后对话可用；断网/凭证失效时有明确错误提示，不白屏

## 四、非目标（明确不做）

- 不重写 UI（直接复用朱峰现有无限桌面前端）
- 不做用户系统/账号体系（复用朱峰账号）
- 不做模型代理服务器（v1.1：只做轻量鉴权接口，流量直连）
- 不承担 ZCode 用户的网络流量与模型算力成本（v1.1 修正：模型成本由用户朱峰账号按 Token 承担）

## 六、风险与对策（吸收前几轮反驳教训）

| 风险 | 对策 |
|---|---|
| ZCode 插件 API 能否注册命令/按钮未实测 | P0 第一天先做 hello-world 插件探针（半天），不通则退化为「独立快捷方式」形态（价值仍存，体验略降） |
| 安装包硬编码本机路径 | 安装脚本运行时探测 Python/资源路径，自带最小依赖 |
| record_read 暴露隐私记忆 | bridge-lite 只挂 UI 必需的白名单 API，**默认不挂记忆读取** |
| 引擎桥三条通道全部不通 | 兜底形态 c：UI 做纯监控/展示面板，价值降级但可交付 |
| fastmcp 版本漂移 | bridge-lite 核心用纯标准库，零第三方依赖（pywebview 为窗口壳独立可选项） |
| **WebView2 缺失（v1.1 新增）** | 自动退回系统默认浏览器打开，功能不缺失 |
| **朱峰凭证泄露（v1.1 新增）** | 凭证只存本地加密，绝不下发明文 key；线路列表远程可开关 |

## 七、实施顺序

1. D1：ZCode 插件 hello-world 探针（命令注册+弹窗，验证插件 API）
2. D2-3：zf-bridge-lite 骨架（静态托管+动态端口+健康检查）
3. D4-5：按钮→pywebview 原生窗口唤起全链路（含浏览器兜底）
4. D6-8：引擎桥通道 a/b 调研与实现（失败走 c 兜底）+ 朱峰线路鉴权接通
5. D9-10：验收四项标准实测 + 打包
