## 现状盘点（已实锤）
- 角色库 `private/roles_db.json` 现有：策划师/反驳师/审核师/施工师/总结师等，**无「进化师」**。
- 进化基础设施已存在但不"出题"：capability_tree（涌现候选 emerge/confirm/reject 需人工裁决）、evolution_lab（千轮自进化+四闸门，只跑不选题）、race.py 赛马（只比怎么进化）。
- 现有角色全是**回顾型**；无前瞻型角色回答"下一步该进化什么"。
- 反驳师 2026-10-23 落地，观察期模板已钉死，数据刚起步——角色通胀风险真实存在。
- 可抄先例：反驳师落地链路（roles_db 角色+独立窗口+徽章+观察期淘汰线）已实跑验证通过。

## 一、任务计划（阶段/依赖）
- **P0（先行，零代码）**：立"进化课题池"——反驳师报告、调查黑板、赛马故障复盘中**重复问题模式**手工记入 `private/记忆/进化/课题池.md`。依赖：无。调查黑板 2026-10-23/24 反驳归档可作首批素材。
- **P1（判据触发）**：课题池同一模式复现 ≥3 次 → 正式立项。依赖 P0；可引用反驳师观察期记录作判据。
- **P2（零代码落地）**：roles_db.json 加「进化师」角色（照抄反驳师套路：专属分区「进化/」+落盘规范+触发分级守则+淘汰线）。依赖 P1 裁决。
- **P3（可选，少量代码）**：swarm_pipeline.py 新增"进化"阶段或 schedule 周任务，输入=进化树+emerge_pending+反驳/调查黑板归档，输出=《进化课题建议书》落盘「进化/」。依赖 P2 稳定运行 2 周。

## 二、实现方法
- P2 照抄反驳师落地记录：① roles_db.json 新增角色（id/group/order，落盘分区「进化」）；② prompt 职责=读 capability_tree(emerge_pending)+反驳/归档+调查黑板 → 提炼重复模式 → 出课题（每课题含：证据≥3处、建议交给 race.py/evolution_lab/人工哪条线、预期收益）；③ 淘汰线：连续3份建议书无一课题被采纳 → 收缩为手动。
- 坑：① roles_db.json 改动可能不入 git（正常）；② 与策划师划界——策划师面向单任务，进化师面向跨任务模式；③ emerge 候选是现成输入源，勿另造数据结构；④ best_practices 回声室前车之鉴——进化记忆须有淘汰。

## 三、愿景
蜂群从"回顾闭环"（策划→反驳→施工→审核→总结）补上"前瞻闭环"：进化师定期消化记忆，把反复踩的坑变成课题，喂给进化实验室/赛马出题，形成 记录→提炼→出题→进化→沉淀 的自我改进飞轮；进化树画布即飞轮仪表盘。

## 四、风险与备选
- 角色通胀/成本上涨 → P1 判据闸门前置；备选=把"出题"写进总结师 prompt 增量一句（最省）。
- 与策划师/涌现侦测重叠 → prompt 明确"只做跨任务模式提炼"。
- 建议书空泛八股 → 每课题强制 ≥3 处记录证据，否则整份作废。
