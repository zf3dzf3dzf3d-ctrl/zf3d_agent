# 策划案：峰控手机版独立仓库拆分方案

> 撰写日期：2026-10-24 ｜ 现状基于 5.7.0 主仓 `手机版/` 目录实查

## 一、为什么要拆

1. **职责分离**：主仓是 PC 端智能体（server + public + python），手机版是独立 Android 工程（Gradle/Kotlin），构建工具链完全不同，混在一起互相拖累。
2. **主仓越来越重**：手机版含 `.gradle/`、`app/build/`、多个历史 APK（v99/v100/v104/v105，单个几十 MB）、`zf.keystore`，这些都不该出现在主仓。
3. **独立发版**：APK 版本号（v105 → v106…）应独立打 tag/发 release，不跟主仓 5.7.0 → 5.8.0 的版本走。
4. **安全**：`zf.keystore`（签名密钥）、`local.properties`（SDK 路径）绝不能随主仓扩散，独立仓库可以更干净地做 .gitignore。

## 二、现状盘点（手机版/ 目录实查）

| 内容 | 处理 |
|---|---|
| `app/`（Kotlin 源码 + assets/web 桥接资源） | ✅ 迁移，仓库核心 |
| `gradle/`、`gradlew(.bat)`、`*.gradle.kts`、`gradle.properties` | ✅ 迁移 |
| `termux/`（boot_bridge、cron、morning_report 等脚本） | ✅ 迁移 |
| `share/zf_peak_scripts/`（AutoX 桥、mihon_dl 脚本） | ✅ 迁移 |
| `gen_icons*.py`、`README/BUILD/PROGRESS.md`、`.gitignore` | ✅ 迁移 |
| `zf.keystore` | ⚠️ **不进 git**，本地保留 + 异地备份（网盘/U盘），新仓 .gitignore 排除 |
| `local.properties` | ❌ 不迁移（每台机器 SDK 路径不同，Android Studio 自动生成） |
| `.gradle/`、`app/build/`、`_archive/`、`*.apk` | ❌ 不迁移（构建产物/缓存），留原处或删除 |
| `*.bak.*`（5 个 build.gradle.kts 备份） | ❌ 不迁移，git 历史即备份 |

## 三、目标仓库结构

新仓库名建议：`zf-peak-mobile`（或 `zhufeng-fengkong-mobile`）

```
zf-peak-mobile/
├─ app/                      # Android 主模块
├─ gradle/ + gradlew         # wrapper
├─ build.gradle.kts / settings.gradle.kts / gradle.properties
├─ termux/                   # Termux 桥接脚本
├─ share/zf_peak_scripts/    # AutoX/自动化脚本
├─ scripts/gen_icons*.py     # 图标生成工具（收进 scripts/）
├─ docs/ (README.md BUILD.md PROGRESS.md)
├─ releases/                 # 仅放最新 APK 或用 GitHub Release
└─ .gitignore                # 排除 keystore/local.properties/build/.gradle/*.apk
```

## 四、迁移步骤（可执行清单）

1. **建仓**：`git init zf-peak-mobile`（本地）→ 推到远端（GitHub/Gitee 私有仓）。
2. **复制文件**：按上表 ✅ 项复制（可用 `robocopy 手机版 zf-peak-mobile /e /xf local.properties *.apk *.bak.* /xd .gradle build _archive`）。
3. **写 .gitignore**：
   ```
   *.apk
   *.keystore
   local.properties
   .gradle/
   build/
   *.bak.*
   ```
4. **首次提交**：`git add` 逐项确认后 commit "init: 从主仓 5.7.0 迁移峰控手机版"。
5. **验证构建**：Android Studio 打开新仓库，`assembleDebug` 通过 → 产出 APK 与 v105 一致性目检。
6. **主仓瘦身**：确认新仓构建无误后，把主仓 `手机版/` 从工作区移除（保留 keystore 与最新 APK 先备份到 `_archive_keystore/` 私有位置）；主仓 README 的"手机版"章节改为指向新仓库链接。
7. **主仓提交**：`git rm -r --cached 手机版` + 更新 .gitignore，commit "手机版拆分至独立仓库 zf-peak-mobile"。
8. **打 tag**：新仓 `v105-migrate` 作为基线，此后 APK 独立发版。

## 五、风险与注意

- ⚠️ **keystore 千万别推到远端**，泄漏 = 任何人可发同签名 APK；丢失 = 无法覆盖安装升级。建议单独加密备份 2 份。
- 主仓 git 历史里可能已含 keystore/APK（需 `git log --all -- 手机版/zf.keystore` 实查）；若已入库且要推公网，需 filter-repo 清史或主仓保持私有。
- 手机版 WebView 加载的是主仓 server 的 Web UI，两仓库存在**运行时耦合**：新仓 README 必须写清配套主仓版本要求（如 "需搭配 5.7.0+ server"）。
- `share/zf_peak_scripts` 若与主仓脚本有同名重复，后续可考虑 git submodule 统一，P2 再做不急。

## 六、分期节奏

- **M1（半天）**：建仓 + 迁移 + 构建验证。
- **M2（半天）**：主仓瘦身 + README 互链 + keystore 异地备份。
- **M3（后续）**：远端私有仓推送、CI 自动打包（GitHub Actions assembleDebug）、Release 发版流程。
