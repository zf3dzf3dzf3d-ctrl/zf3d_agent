- 健康度：P0=P1=0，零改动收口

## 进化方向（按优先级）

### E1 五件套归属单一化【P2 转正，低风险快赢】
- 问题：image_gen / video_gen / video_edit / set_camera / monitor 在「视觉工具」与「编程」双罗列
- 方案：靠 includes 继承解决——视觉工具类已有 includes=极简；把五件套从「编程」罗列中移除，改由视觉分类承载，编程类需要时通过二级入口访问
- 风险：会改变编程分类下直接罗列的可见性 → 改前跑一遍盘点脚本对比 defs 快照，确认运行时注入集合不变
- 验收：getDefinitions() 输出集合前后 diff 为空，仅分类 UI 罗列变化

### E2 工具元数据补全：成本/耗时/成功率标注【中】
- 现状：工具 defs 只有名称/描述/schema，AI 选工具纯靠文字猜
- 方案：tools-defs-*.js 增加可选字段 cost_hint（低/中/高 token）、avg_ms、risk_level（只读/写入/联网/付费）；在 server 端做调用统计回写（复用 gate_summary 思路），前端 tooltip 展示
- 价值：智能体选工具可参考实测成本，减少「大炮打蚊子」式调用

### E3 分类动态装载（按需 extends）【中，架构向】
- 现状：编程/写作分类一次性 34/41 个工具全量注入 prompt，token 开销大
- 方案：分类支持「核心集 + 扩展集」，AI 先见核心集，需要时 switch_tool_category 精确拉取（机制已有，缺的是分类内的分层定义）
- 验收：同任务下 prompt 工具段 token 下降 ≥30%，任务完成率不降

### E4 幽灵/孤儿工具巡检常态化【低，防回归】
- 方案：盘点工具区.py 升级为 CI 式巡检：①defs 注册但未入任何启用数组 → 孤儿告警；②启用数组引用但无 def → 幽灵告警；③.bak 文件混入 defs 目录检测
- 落点：cron/每日 schedule 跑一次，结果写 journal

### E5 工具自进化闭环（对接 capability_tree）【远期】
- 思路：每次工具调用成功/失败写入 emergence_event，连续成功率高但 clarity 低的工具自动建议「转正/提权」（如从极简升入常驻）；连续失败工具建议下架修复
- 依赖：capability_tree emerge 侦测开关（当前 off）
