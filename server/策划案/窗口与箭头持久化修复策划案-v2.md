# 策划案 v2：画布窗口丢失 + 箭头不持久化 修复方案

> 版本：v2（覆盖此前版本：策划案\窗口与箭头持久化修复策划案.md v1；private/记忆 写入被系统拦截，本文件为唯一真源）
> 日期：2026-10-30 ｜ 诊断依据：项目记录「重启前快照-窗口与箭头」「重启后比对-窗口与箭头」

## 一、根因（已实测，锁定结论）
1. **箭头丢失**：app-canvas-arrows.js 保存链路 UserSettings（键 zf3d_canvas_arrows）→ /api/user-settings → private\用户设置\user_settings.json，实测该文件 0 命中 → 保存从未成功落盘。前端仅 localStorage 兜底；且尾部 user-settings-refreshed 回调存在「旧数据回写覆盖新值」竞态风险。
2. **窗口丢失 3 个**：api_dispatch_delete.py:82 对 canvas_nodes 物理 DELETE，不写 trash_items，删除不可恢复。
3. 服务端已有 /api/user-settings GET/POST（api_dispatch_get.py:904），可直接复用。

## 二、任务计划（阶段依赖：A→B 可并行，C 依赖 A、B 完成）

### 阶段 A：箭头持久化修复（第一优先，当前数据持续丢失中）
- A1 排查丢键原因（0.5d）：UserSettings.set 埋日志 + 复现画箭头，确认是 ①POST 未发出 ②服务端白名单拒收 ③storage-guard 清理 ④refresh 竞态旧值回写。四种嫌疑逐一对照实验定罪，不许选一个直接开修（排查纪律铁律2）。
- A2 保存链路加固（0.5d）：
  - saveAll 写后读校验：POST 后 GET 回读 zf3d_canvas_arrows，条数不一致 console.warn + 重试 1 次；
  - refresh 回调加 _dirty 标记：仅本地有未保存修改才响应服务端刷新回写，防旧值覆盖；
  - loadAll 兜底：localStorage 有值而服务端无值 → 先渲染并立即 saveAll 同步服务端。
- A3 beforeunload 强制 flush（0.2d）：拖完箭头立刻重启场景，300ms 防抖会吞最后一次改动；unload 时同步 POST（失败退化为 sendBeacon）。

### 阶段 B：窗口软删除（可独立并行）
- B1 api_dispatch_delete.py:82 前，整行 JSON 化插入 trash_items(source='canvas_nodes', data=原行, deleted_at=now)（0.5d）。只改 canvas_nodes 分支，复用现有 DB 写路径，勿绕过 WAL 新开连接。
- B2 新增 POST /api/trash/restore（0.5d）：反序列化重插 canvas_nodes，id 冲突生成新 id，恢复后前端刷新画布。
- B3 前端「回收站」入口（可后置，先保证数据不丢）。

### 阶段 C：回归验证（依赖 A、B，0.5d）
复用既有快照比对脚本：画多个不同角度箭头 + 删 1 窗 → 重启 → 核对 ①箭头位置/角度原样恢复且 user_settings.json 有键 ②trash_items 有被删窗口行且可恢复 ③既有 22 窗坐标零变化。复跑两次。

## 三、愿景
重启彻底无损：窗口数量/坐标/层级、箭头位置/方向，重启后原封不动；误删窗口从回收站一键还原；快照比对脚本固化为常备工具，任何改动后一键验证持久化完整性；后续推广到连线、视口等全部画布元素。

## 四、风险与备选
1. user-settings 接口可能有键白名单/长度限制 → 备选：箭头改存 DB 新表 canvas_arrows（照 canvas_nodes 模式）+ 专用接口。
2. 软删除致 trash_items 膨胀 → 备选：保留 30 天定期清理，restore 限单条。
3. beforeunload 同步 POST 被浏览器中断 → 备选：sendBeacon；再退化缩短防抖至 100ms。

## 六、反驳项
反1：refresh 竞态只是推断未经证实，若真因是白名单拒收，加 _dirty 无效 → 应对：A1 排查先行且四种嫌疑逐一对照实验，白名单拒收则按风险1备选改走 DB 专表。
反2：api_dispatch_delete.py 管多张表，软删除改动可能波及其他表 → 应对：只改 canvas_nodes 分支，改前 grep 全部调用点并审计，回归验证其他表删除不受影响。
反3：当前箭头 0 条孤例，修完无法确认真场景恢复正确 → 应对：回归阶段画多类型箭头（不同角度/起止点）批量验证，快照比对脚本复跑两次。
