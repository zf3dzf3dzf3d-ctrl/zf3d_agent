# 策划案：工作台员工集成 Skill / MD / MCP（v2 全自动方案）

> 版本 v2.0 ｜ 2026-11 ｜ 状态：**已废弃（并入 v3 定稿）**
> ⚠️ 本方案已被《private/记忆/策划案-员工集成skill-md-mcp-v3定稿》取代（2026-10-31 蜂群收口裁决），
> 施工以 v3 为唯一真源。本文件保留作历史参考，勿按此施工。
> 结论先行：**零人工选择，全自动智能挂载**。用户不做任何勾选，规则只有一条默认——
> **「员工 = 主智能体的能力子集 + 自动检索的 md 知识 + 按需 MCP」**。特殊需求才在 persona 里写一句话自定义。
> （v1 多选挂载方案保留为备选，作为未来的"高级模式"入口，见 §6）

---

## 一、为什么改版

v1（多选挂载）功能完整但需要用户逐员工勾选 skills/docs/mcp，配置成本高。用户明确表态：**不想选、也不想人工挑 md**。因此 v2 把"人工选择"替换为"自动推断 + 自动检索"，做到零配置即可享受全部增强。

## 二、三大自动机制

### 2.1 MD 知识：自动检索注入（不挑文档，按需命中）

员工收到任务时，系统把**任务描述**与知识库做相似度匹配，自动把命中的 md 片段拼进上下文：

- **知识库范围**：`private/记忆/`、`项目记录/`（两处都是现成的喂料口，用户平时写，员工自动会用）。
- **匹配方式（分两档）**：
  - v2.0（本期）：关键词/TF-IDF 打分，取 Top N 片段（每片段 ≤1500 字，总量 ≤6000 字），纯 Python 实现，无新依赖；
  - v2.1（可选）：embedding 相似度，需要向量化服务时再上。
- **效果**：您往记忆目录写一份《引擎笔记.md》，"游戏导师"员工下次接到相关任务自动带上它，无需任何配置动作。

### 2.2 Skill：persona 自动推断 + 默认继承

- **默认规则**：员工未声明时，**继承主智能体当前启用的全部工具分类**（与现状行为一致，零风险）。
- **自动裁剪**：按 persona 关键词匹配自动收窄，例如：
  - persona 含 文案/写作/编辑 → 自动配 写作分类；
  - persona 含 代码/程序/开发 → 自动配 编程分类；
  - persona 含 浏览/网页/调研 → 自动配 browser 等；
  - 敏感工具（send_email、schedule 等）无论怎么匹配，员工默认不可用。
- **一句话自定义**：persona 里写"可用全部工具"= 全量继承；写"禁用 XX"= 排除。用户最多写一句话，大多数情况什么都不用写。

### 2.3 MCP：按需自动分发

- **默认**：fetch（网页抓取）类无风险 MCP 对员工自动可用；
- windows-mcp 等系统级 MCP 仅当任务描述/persona 命中"系统操作/文件/窗口"类意图时临时挂载，任务结束即回收；
- 同样支持 persona 一句话覆盖。

## 三、数据模型（极简，用户不可见）

team.json 角色条目只加**一个**内部字段：

```json
{
  "name": "游戏导师", "persona": "…", "fields": [...],
  "auto_cap": true          // 默认 true：启用自动能力推断；false = 回退旧行为
}
```

- 不存 skills/docs/mcp 列表（那是 v1 高级模式才需要的）——自动方案的能力是**每次任务运行时动态计算**的，天然无配置漂移。
- 向后兼容：老 team.json 无此字段 = 按 true 处理，但知识检索命中规则保守（仅 private/记忆/），行为与现状几乎一致。

## 四、运行时链路

```
员工被唤醒执行任务
  → 组装 system：persona
       + 【自动知识】任务描述×知识库 打分 Top 片段（标注来源文件，员工可要求读全文）
  → 组装工具表：主智能体启用分类（按 persona 自动裁剪）+ 按需 MCP
  → 执行；调用层仍做白名单拒绝（软隔离，与 v1 相同）
```

改动点：
- `butler_store.py`：team.json 增加 auto_cap 字段 + 校验（小）；
- 员工唤醒链路组装处：接"知识打分模块 + 工具推断模块"（中，核心工作量）；
- 新增 `server/butler_knowledge.py`：关键词打分检索（~100 行，无依赖）。

## 五、验收标准

- [ ] 用户全程零操作：新建员工 → 派任务 → 员工上下文自动含命中记忆片段（日志/工具可查注入了哪些文件）。
- [ ] persona 写"文案专员"的员工自动获得写作分类工具，调用编程类被拒。
- [ ] 敏感工具（send_email/schedule）员工任何情况不可用。
- [ ] 老员工（无 auto_cap 字段）行为与升级前一致。
- [ ] 知识检索空命中时 system 不注入空段落，无报错。

## 六、v1 方案的去留

- v2 为默认模式（auto_cap=true），**无任何 UI**；
- v1 的三层多选抽屉降级为"高级模式"，未来若出现"某个员工就是需要固定挂某份文档"的硬需求再实现（预计 P3 期，非必需）。

## 七、风险与决策点

1. **关键词检索精度**：无 embedding 时可能漏配/错配片段——缓解：注入内容带来源标注，员工可主动要求读全文；决策点：是否接受 v2.0 用关键词、后续再上 embedding。
2. **自动裁剪误伤**：persona 推断可能给"文案"员工裁掉它需要的浏览器——缓解：默认倾向多给（只裁敏感工具），裁剪规则保守。
3. **性能**：每次任务做知识打分，知识库 <500 篇 md 时纯 Python 打分 <50ms，可接受；超过后再考虑缓存/向量索引。
