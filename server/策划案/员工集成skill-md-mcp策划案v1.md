# 策划案：工作台员工集成 Skill / MD / MCP（多选挂载）

> 版本 v1.0 ｜ 2026-11 ｜ 状态：待评审
> 结论先行：**建议集成，且做成"多选挂载"**——每个员工可自由勾选若干 skill、若干 md 知识文档、若干 MCP 服务器，三选任意组合，不互斥。

---

## 一、为什么需要（价值判断）

现状：员工（butler 角色）只有 `persona`（一段人设文字）+ `fields`（档案抽取字段），见 `server/butler_store.py`。能力天花板 = 纯文本人设，存在三个瓶颈：

1. **无专属技能**：员工和主对话共享同一套工具分类，无法表达"这个员工只会用浏览器 + 文生图"。
2. **无专属知识**：想让"游戏导师"常驻一份引擎笔记/项目规范，只能塞进 persona，越写越长。
3. **无专属外挂**：MCP（`server/mcp_servers.json` 已有 windows-mcp、fetch）是全局的，不能按员工分配，权限粒度太粗。

集成后员工从"一段人设"升级为"**人设 + 知识 + 技能 + 外挂**"的完整智能体单元。

## 二、总体设计

### 2.1 数据模型（team.json 角色条目扩展 3 个可选字段）

```json
{
  "name": "游戏导师", "avatar": "🎮",
  "persona": "…",
  "fields": ["project", "decision", "milestone"],
  "skills": ["browser", "code_run"],          // 多选：工具分类/技能包 key 列表
  "docs": ["private/butler/游戏导师/引擎笔记.md"],  // 多选：md 文档路径列表
  "mcp": ["windows-mcp", "fetch"]             // 多选：mcp_servers.json 里的服务器名
}
```

- 三个字段全部**可选**，留空 = 维持现状（继承全局默认工具），向后兼容。
- 校验：skills 必须 ∈ tools-defs-categories.js 启用数组；mcp 必须命中 mcp_servers.json 白名单；docs 限定在 `private/` 目录内（防路径穿越，参照 butler_store 现有 role 白名单做法）。

### 2.2 生成时机

- **AI 生成员工时**（app-project-panel.js 的 promptGenMember 流程）：AI 设计岗位时可一并给出 skills/docs/mcp 建议，落 team.json。
- **工作台手动编辑**：团队页（👥 团队标签）给每个员工卡片加"⚙ 能力配置"入口，弹三层多选清单：
  - Skill：复选工具分类（极简/编程/写作…）或技能包；
  - MD：文件选择器（扫 private/butler/<角色>/ 及 private/记忆/ 下 .md，也支持新建空文档）；
  - MCP：复选 mcp_servers.json 中已注册服务器，附"去 MCP 管理页添加"跳转。

### 2.3 运行时注入（核心链路）

员工被唤醒执行任务时，组装上下文的顺序：

```
system = persona
       + "\n\n【专属知识】\n" + docs 内容（每篇限长，如 4000 字，超出给摘要+按需读全文指引）
       + 工具清单 = skills 多选合并去重（未配置则用全局默认）
       + MCP 工具 = mcp 多选的服务器工具并入 function 定义表
```

- **工具分发硬约束**：员工会话调用工具时按其 skills/mcp 白名单过滤，不在白名单的工具调用直接拒绝并提示"该员工无此权限"。
- **MD 知识**：不做 RAG（当前规模不需要），直接拼接 + 字符上限截断；超长文档建议拆篇。
- **主脑/主对话不受影响**：主对话保持全量工具，仅员工被收窄。

### 2.4 权限与安全

| 项 | 规则 |
|---|---|
| skills 白名单 | 后端二次校验，前端选项只是 UX |
| mcp 白名单 | 只允许启用 mcp_servers.json 中已注册项，不允许员工配置内联新命令 |
| docs 路径 | 必须以 `private/` 开头且规范化后无 `..` |
| 敏感工具 | 如 send_email、schedule 等标记 `admin_only`，员工 skills 多选里默认不可勾（除非全局开关放行） |

## 三、UI 草案（工作台 👥 团队页）

员工卡片新增角标区：`🧩3技能 📄2文档 🔌1MCP`，点击进入配置抽屉：

```
┌ 能力配置：游戏导师 ────────────┐
│ ① 技能包(多选)  ☑编程 ☑极简 ☐写作 ☐浏览   │
│ ② 知识文档(多选) ☑引擎笔记.md ☑项目规范.md │
│                  [+新建] [+从记忆库选择]    │
│ ③ MCP服务器(多选) ☑windows-mcp ☐fetch     │
│                   [管理 MCP →]            │
│              [保存] [恢复默认]             │
└──────────────────────────────┘
```

## 四、实施排期（建议 3 期）

| 期 | 内容 | 改动点 | 工作量 |
|---|---|---|---|
| P1 | 数据模型 + 后端注入 | butler_store.py（team.json 扩展+校验）、员工唤醒链路（dispatch/loop 组装处）拼 persona+docs+工具过滤 | 中 |
| P2 | 工作台配置 UI | app-project-panel.js 团队页：角标 + 多选配置抽屉 + 新建/选文档 | 中 |
| P3 | MCP 按员工分发 | MCP 工具表按员工过滤并入 function 定义；管理页跳转 | 大（依赖现有 MCP 客户端改造） |

## 五、风险与决策点

1. **是否需要 RAG**：v1 不做。文档多了以后再评估（决策点：docs 上限定 5 篇/员工）。
2. **员工权限隔离深度**：当前员工与主对话共用执行环境，工具过滤是"软隔离"（提示层+调用层拒绝），不做沙箱硬隔离——够用且成本低。
3. **mcp_servers.json 挂了怎么办**：员工配置里引用的服务器失联时，注入时跳过并在卡片角标显示 ⚠。
4. **向后兼容**：老 team.json 无新字段 = 行为不变，零迁移成本。

## 六、验收标准

- [ ] 给某员工配置 skills 后，该员工会话中调用白名单外工具被拒，白名单内正常。
- [ ] 配置 docs 后，该员工 system 中可见文档内容，且总量超限时被截断不报错。
- [ ] 配置 mcp 后，该员工可用对应 MCP 工具；未配置员工看不到。
- [ ] 三字段全空的旧员工行为与升级前完全一致。
- [ ] 工作台可完成全部配置操作，刷新后配置持久化（team.json 落盘）。
