# 策划案：密闭环境 1000 轮多智能体自进化实验（调研版 v1）

## 一、现有基础设施盘点（调研结论）

已有可复用组件（server/ 目录）：

| 组件 | 文件 | 现状 | 对本实验的价值 |
|---|---|---|---|
| 蜂群流水线 | swarm_pipeline.py | ✅ 成熟。策划→收口裁决→施工→审核→总结五阶段串行，产物落库+落盘 | **核心引擎**。天然多智能体协作闭环，但一次只跑一轮 |
| 单次执行 | cli.py `run_once()` | ✅ 完整 agent 工具循环，能真正改代码 | 施工阶段的执行器 |
| 服务端 ReAct 循环 | loop_s.py + loop_host_config.py | ✅ 内核化循环，MAX_TURNS 防失控、循环检测（同签名去重）、SSE 事件流 | 提供防失控的工程范式（签名去重/事件上限） |
| 养成系统 | growth_engine.py | ✅ 经验/等级/技能树，日封顶防刷 | 可作为"进化评分"的可视化外壳 |
| 能力进化树 | capability_tree（三表+渲染） | ✅ 播种/证据/涌现侦测/确认 | **进化记录的天然数据结构** |
| 沙箱配置 | private/沙箱配置.json | ⚠️ 仅 `{"mode":"docker","mem_mb":1024}` 占位声明，**没有真正的 Docker 隔离实现** | 密闭环境需要自建，这是最大缺口 |
| 沙箱路由 | routes/mixin_sandbox.py | 存在 | 待核实实现深度 |
| 网络防护 | network_guard.py / path_guard.py | 存在 | 可复用做密闭墙 |

**结论：具备"多智能体协作 + 循环执行 + 进化记录"三块地基，缺的是 ① 轮次宿主（外层 1000 轮循环器）② 真密闭沙箱 ③ 进化反馈回路（上一轮产物→下一轮输入的自动机制）④ 成本/止损闸门。**

## 二、目标定义

在一个不接触真实工作区、不外呼（除模型 API）的密闭环境中，让多智能体蜂群自主跑 1000 轮「策划→施工→审核→进化」，每轮基于上一轮结果自我改进，全程可观测、可中断、可回滚。

## 三、总体架构（新增 1 个宿主 + 3 个模块）

```
evolution_lab/  (新建，与 server 主工作区物理隔离)
├── workspace/          # 智能体唯一可写的"世界"（git init，每轮一 commit，可回滚）
├── runner.py           # 1000 轮外层宿主
├── sandbox.py          # 密闭墙（路径白名单+网络白名单）
└── evolution.py        # 进化反馈回路
```

### 3.1 密闭环境 sandbox.py（最大缺口，优先做）
- **路径密闭**：复用 path_guard 思路，施工阶段 cwd 强制设为 `evolution_lab/workspace/`，拒绝一切绝对路径越界写。
- **网络密闭**：除模型 API 白名单域名外，run_code 内嵌代理拦截（环境变量 HTTP_PROXY 指向本地丢弃代理，或 patch urllib/requests）；浏览器工具直接禁用。
- **资源密闭**：Windows 下用 Job Object 限内存/CPU（替代 docker 声明）；每轮超时硬上限（如 15 分钟）。
- **git 快照墙**：workspace 每轮开始打 tag，审核不过 `git reset --hard` 回滚，毒轮不留痕。

### 3.2 轮次宿主 runner.py
- 外层 `for round in range(1, 1001)`，每轮调用一次 `swarm_pipeline.run_pipeline()`，goal 由 evolution.py 生成。
- 每轮产出落 `evolution_lab/journal/round_XXXX.md` + 落库 agent_turns（session_id 加 lab 前缀，与前台互通可观测）。
- 状态机：running / paused / aborted，支持断点续跑（journal 是唯一真源）。
- **止损闸门**（直接抄 loop_s.py 的工程范式）：
  - 连续 N 轮（如 5）审核不过 → 自动暂停待人工介入；
  - 同签名任务重复计数（循环检测）→ 换 goal 注入扰动；
  - token 消耗日封顶（复用 zf_billing 统计）。

### 3.3 进化反馈回路 evolution.py
- **任务生成**：每轮结束由"总结师"输出下一轮 goal 候选（自举），加固定约束清单（密闭墙规则、代码质量红线）防漂移。
- **评分**：审核阶段已有通过/不过二元；扩展为多维分（正确性/进度/多样性），写入 journal。
- **进化记录**：每轮识别出的新能力/新技巧 → `capability_tree.emerge` 候选入库，人工/自动确认后 clarity 上升；1000 轮结束 render 出进化树。
- **多样性扰动**：连续多轮评分平台期时注入随机方向提示（防"回音室"，复用 echo_breaker 思想）。

### 3.4 与主系统的关系
- 实验期间 `loop_host` 不动、主工作区不动；lab 是平行世界。
- 前台可观测：journal + agent_turns + capability_tree 渲染页，加一个只读面板（可选，二期）。

## 四、实施步骤

| 阶段 | 内容 | 验收 |
|---|---|---|
| P1 沙箱 | sandbox.py：路径/网络/资源/回滚四面墙 | 越界写/外呼/超时均被拦截，单测通过 |
| P2 宿主 | runner.py：10 轮试点（非 1000） | 断点续跑、止损闸门生效 |
| P3 进化 | evolution.py：goal 自举+评分+能力树埋点 | 10 轮内能力树有真实涌现节点 |
| P4 全量 | 1000 轮正式跑（预估按 token 成本先算账） | journal 完整、进化树可渲染 |

## 五、风险与前置确认
1. **成本**：1000 轮 × 五阶段 × 多智能体 ≈ 数千~数万次模型调用，需先确认预算与模型渠道配额。
2. **自举漂移**：goal 自我生成可能跑偏 → 约束清单+周期性"锚点目标"强制注入。
3. **Windows 无 docker**：密闭靠进程内防护而非容器，强度弱于真容器；如需强隔离，建议后续装 Docker Desktop 切换 mode。
4. **审核瓶颈**：审核者也是模型，可能"放水"→ 关键轮抽查人工复核。

## 六、已拍板项
- ① 主题：**两者混合**——前期（约 1~300 轮）在密闭环境内从零造软件，后期（约 300~1000 轮）转为改进智能体自身 prompt/工具/蜂群流程。
- ② 沙箱强度：**进程内防护**（路径/网络白名单 + git 回滚），不依赖 Docker。
- ③ 当前阶段：**只做成本估算，不实际开跑**。

## 七、成本估算（1000 轮）

按 swarm_pipeline 单轮结构估算：

| 阶段 | 调用方式 | 次数/轮 | 单次 token 估 | 小计/轮 |
|---|---|---|---|---|
| 策划×2 | 轻量 _chat | 2 | ~3k | 6k |
| 收口裁决 | 轻量 _chat | 1 | ~3k | 3k |
| 施工×1 | 完整 agent 循环 | 1 | ~10~50k（均 30k，含工具往返） | 30k |
| 审核×2 | 轻量 _chat | 2 | ~3k | 6k |
| 总结 | 轻量 _chat | 1 | ~3k | 3k |

- **单轮 ≈ 5 万 token 上下（输入+输出合并口径）**，取 50k。
- **1000 轮 ≈ 5000 万 token**。止损闸门正常工作下按 80% 完成率计 ≈ **4000 万 token**。

按典型定价折算（单价请按实际渠道核对）：
- 经济档（如 deepseek 类，¥1~2/百万 token）：**¥50~100**
- 中档（¥8/百万 in + ¥20/百万 out，混合约 ¥12/百万）：**¥500~600**
- 旗舰档（¥40+/百万）：**¥2000~5000**

附加成本：
- 试点 10 轮验证 ≈ 50 万 token，成本可忽略，强烈建议先行。
- 人工介入预留：按 5% 轮次触发止损暂停，需人值守抽查。
- 存储/git：journal 1000 份 md + 1000 个 commit，约百 MB 级，无压力。

结论：**经济档全跑 1000 轮成本可忽略；中档约几百元；先跑 10 轮试点（几乎零成本）校准真实单轮 token，再外推精确总账。**
