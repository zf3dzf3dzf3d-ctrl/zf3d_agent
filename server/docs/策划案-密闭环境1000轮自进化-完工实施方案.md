## 二、各模块详细设计

### M1 sandbox.py —— 密闭墙（P0，最大缺口）
**功能点：**
1. 路径密闭：提供 `guarded_run(cmd, cwd)` 包装。施工阶段 cwd 强制 `evolution_lab/workspace/`；写操作前经路径检查函数校验（解析 realpath，拒绝逃逸 `..\`、绝对路径、符号链接出界）。
2. 网络密闭：环境变量注入 `HTTP_PROXY/HTTPS_PROXY=http://127.0.0.1:1`（指向不存在的本地端口=丢弃）；模型 API 走宿主侧代理转发（API 请求由 runner 进程发出，智能体进程本身无外呼能力）。
3. 工具白名单：只放行 读写/运行/search 等；禁用 browser_control、send_email、net、schedule 等外呼类工具。
4. 资源密闭：每轮硬超时（默认 15 分钟，可配）；Windows 下用 `subprocess` + Job Object（pywin32）限内存 1GB；单轮 token 计量。
5. git 快照墙：每轮开工前 `git add -A && git commit` 打基线 tag `round-XXXX-start`；审核不过 → `git reset --hard` 回滚。

**验收：** ① 在沙箱内尝试写 workspace 外路径被拒绝并留审计日志；② `requests.get("https://baidu.com")` 超时失败；③ 恶意轮触发回滚后 workspace 与轮前完全一致（diff 为空）。

### M2 runner.py —— 1000 轮宿主（P0）
**功能点：**
1. 主循环 `for round in 1..1000`，每轮调 `swarm_pipeline.run_pipeline(goal=evolution.next_goal())`。
2. journal 落盘：`journal/round_XXXX.md`（goal/产出/评分/耗时/token），journal 是断点续跑唯一真源。
3. 状态机：running / paused / aborted / cooldown（止损冷却）。支持 Ctrl+C 安全暂停、`--resume` 断点续跑、`--rounds N` 限轮试点。
4. 每轮落库 agent_turns（session_id 带 `lab-` 前缀），前台对话页可回看任一轮完整过程。
5. 崩溃恢复：进程重启后读 journal 最后完整轮，从下一轮继续。

**验收：** `python runner.py --rounds 3` 连跑 3 轮成功产出 3 份 journal；kill 进程后 `--resume` 无重复轮、无漏轮。

### M3 evolution.py —— 进化反馈回路（P0，实验的灵魂）
**功能点：**
1. goal 生成器（三段式课程，对应 v1 方案）：
   - 第 1~300 轮「造物期」：在密闭 workspace 从零写一个软件（如 CLI 工具→带界面的应用），goal 按 milestone 阶梯生成（先"能运行"→再"有功能"→再"有测试"）。
   - 第 301~600 轮「改进期」：读上一轮产物 + 审核意见，goal = 修复缺陷/加功能/重构。
   - 第 601~1000 轮「自指期」：goal 转向改进自身 —— 优化蜂群 prompt、提炼新工具、调整审核标准（写入 `evolution_lab/dna/` 目录，下轮生效）。
2. 评分器：每轮结束由审核阶段产出结构化评分（通过率、功能增量、测试通过数），写入 journal + SQLite（`lab.db`：rounds 表 + scores 表）。
3. 进化记忆：维护 `memory/best_practices.md`（评分高的轮次经验自动摘录，注入后续策划阶段）；同签名任务重复 → 查重并注入扰动。
4. 能力树埋点：评分超阈值的新能力 → 调 capability_tree `emerge` 接口生成候选涌现，人工确认进树。

**验收：** 连续轮次 goal 可见明显演进（journal 抽查）；`lab.db` 有完整评分曲线；涌现候选在进化树页面可见。

### M4 止损闸门（P0，并入 runner）
| 闸门 | 触发条件 | 动作 |
|---|---|---|
| 质量闸 | 连续 5 轮审核不过 | paused，写告警 journal，待人工 resume |
| 循环闸 | 同签名 goal 连续出现 ≥3 次 | 注入随机扰动主题 / 跳课程段 |
| 成本闸 | 单轮 token > 15 万 或 累计超预算 | 立即 abort 当前轮，记 failed |
| 时间闸 | 单轮 > 15 分钟 | kill 子进程，回滚，记 failed |

**验收：** 用故意配置（如超时 1 分钟）验证各闸门独立触发并正确落状态。

### M5 swarm_pipeline 适配（P1，改造现有文件，最小侵入）
- `run_pipeline()` 增加可选参数 `sandbox=None`：传入沙箱上下文时，施工阶段用 `sandbox.guarded_run` 替代直跑、工具集按白名单裁剪；**不传 = 行为与现在完全一致（回归零风险）**。
- 审核阶段输出结构化 JSON 评分（新增字段，向后兼容）。

**验收：** 不传 sandbox 时跑一次现有流程，与改造前输出一致（diff 快照）；传 sandbox 时施工阶段确在 workspace 内执行。

### M6 观测台（P1）
- 新路由 `routes/lab_routes.py`：`GET /api/lab/status`（当前轮/状态/token 累计/评分曲线数据）、`POST /api/lab/pause|resume|abort`。
- 前端新增「进化实验室」页：轮次进度条、评分折线图、最近 journal 摘要、按钮（暂停/继续/中止）。
- 复用前台 agent_turns 会话页看单轮全过程，不重复造轮子。

**验收：** 页面能看到实时轮次与曲线；暂停/继续按钮实际生效。

### M7 进化树/养成打通（P2，锦上添花）
- emergence 候选自动入库 + 前台确认；
- 每轮评分换算成长成系统经验（受日封顶约束）。

### M8 试点与开跑（P0 收口）
1. **10 轮试点**（成本 ≈50 万 token，经济档 <¥1）：校准真实单轮 token、验证四大闸门、检查 journal 完整性。
2. 根据试点数据修订成本外推与课程难度曲线。
3. 正式 1000 轮：建议夜间+白天分段跑，每日人工抽查 journal + 观测台。

## 四、风险与对策
| 风险 | 对策 |
|---|---|
| 智能体逃逸沙箱（写主工作区） | M1 路径校验 + workspace 每轮 git 对比 + 宿主进程与智能体进程分离（智能体无主工作区路径知识） |
| 1000 轮后期「摆烂」（评分平台期） | M3 扰动注入 + 课程难度阶梯 + best_practices 注入 |

| 改造 swarm_pipeline 引入回归 | 默认参数零行为变更 + 改造前后 diff 快照回归测试 |

## 十一、量化验收 KPI 
 
1. 试点 10 轮完成率 ≥90%（≥9 轮产出有效 journal+评分）
2. 正式跑有效轮占比 ≥70%（排除闸门 failed 轮）
3. 造物期结束（第300轮）workspace 内软件可通过自编测试 
4. 自指期出现 ≥3 条被采纳的 DNA 改进（dna/ 目录落盘且下轮评分提升）
5. 全程 0 次沙箱逃逸（审计日志无越界写成功记录）
 
## 十二、失败回滚预案 
 
- 单轮失败：git reset --hard 到 round-XXXX-start，journal 记 failed，下一轮继续 
- 连续失败（质量闸）：paused + 人工介入，resume 从失败轮重跑（不跳号）
- 整体废止：workspace/ 与 lab.db 归档到 evolution_lab/archive/，宿主代码零污染（沙箱改动只存在于 workspace 与 lab- 会话）
- 宿主回滚：整个实验只新增 evolution_lab/ 目录 + lab_routes.py，删除即完全卸载
