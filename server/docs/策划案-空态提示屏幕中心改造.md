# 策划案：空态提示文字移出太空舱 · 全屏居中改造（v1.1，覆盖 docs/策划案-空态提示屏幕中心改造.md v1）

> 真源定稿。v1.1 新增推荐度评分协议；其余方案内容与 v1 一致，以下为完整收敛版。

## 一、现状诊断（行级实证）
| 项 | 现状 | 位置 |
|---|---|---|
| 渲染容器 | `.zfm-sp-empty` 空 div | app-kite-modes.js L2030 |
| 挂载位置 | 太空舱节点 `.zfm-space-station` 内 | ensure() 注入 |
| 定位 | absolute + 220×220 同心圆 + overflow:hidden（圆形裁剪锁死文字在舷窗内） | style-kite-modes.css L894 |
| 内容引擎 | ZFEmptyTips：30 主标语 + 12 chip 池抽 3 + 时段问候 + sessionStorage 去重 + 逐字上浮 | zf-empty-tips.js |

| chip 点击 | openDualPanels 弹创建面板 | L2115-2122 |

根因：容器在太空舱 DOM 子树内 + 同心圆 CSS 裁剪 → 文字"困在"舱内。

## 二、任务计划（三步，串行依赖）
1. **CSS 改造**（style-kite-modes.css）：删 L894 圆形同心定义与 900px 断点缩小规则（L914）；新增 `.zf-empty-overlay` 全屏层（position:fixed; inset:0; z-index:60; pointer-events:none; flex 居中；主标语 14px，chip 自身 pointer-events:auto）。
2. **JS 挂载迁移**（app-kite-modes.js）：ensure()（L2030）不再在太空舱字符串内注入空 div，改为惰性创建 `#zfEmptyOverlay` 挂 body；render/显隐逻辑（L2108-2125）改指向新层，保留 _wasEmpty 边沿与 chip 回调 stopPropagation。
3. **引擎微调**（zf-empty-tips.js）：5 处选择器前缀 `.zfm-sp-empty` → `.zf-empty-overlay`；光环放宽至 420px；标语句长上限 ≤18→≤22 字；动画/抽签/去重零改动。

依赖：1→2→3 顺序执行（新层样式先行，迁移后引擎才能命中新选择器）。

## 三、实现方法与坑
- 坑1：旧 keyframes（zfmSpEmptyFloat/Glow）仅旧容器使用，一并删，避免死代码。
- 坑2：`_chk.js` 为 node --check 临时副本，页面不加载，不改，CSS 留注释说明。
- 坑3：fixed 层不随画布拖动属预期（屏幕中心恒定），验收时勿误判为 bug。
- 回滚：纯前端 3 文件替换式改动，git revert 单 commit。

## 四、交互边界
无对话→全屏层显示；创建首个对话→淡出；删光→边沿重渲染换标语；chip 点击→弹创建面板；<900px→12px 换行；刷新→sessionStorage 去重不重复标语。

## 五、愿景
空画布成为"欢迎页"：屏幕正中央一句轮换标语 + 3 枚灵感 chip，点击即建对话；太空舱圆窗回归纯装饰（星空+数字雨）。可扩展：标语池按用户使用习惯加权抽签、chip 支持用户自定义、空态接入节假日主题皮肤。

## 六、风险与备选
- z-index=60 压低层浮动 UI → 层穿透+chip 局部接收，冲突面极小；备选 top 调 48%。
- 备选方案 B：不动 DOM 挂载点，仅改 CSS 为 fixed 居中 + overflow:visible（改动最小，但文字仍属太空舱子树，随舱显隐，语义欠佳，作降级预案）。
