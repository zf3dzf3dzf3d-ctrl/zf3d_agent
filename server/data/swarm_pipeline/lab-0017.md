## 三、被采纳方案【反驳项】逐条回应（必答项）

### 反1：todo.json 可能被审核认定"运行垃圾文件" → **成立，列入改动要点**

### 反2：argparse 异常 exit 2 ≠ 验收要求的 exit 1 → **成立，列入改动要点（并修正原应对）**
- 判定：成立。且策划案原应对有技术瑕疵——`parser.error()` 本身就是 exit 2，靠它无法统一为 1
- 修正做法：自定义 ArgumentParser 子类**覆盖 error()**（打印用法到 stderr 后 `sys.exit(1)`），或在 main 中捕获 SystemExit 并将 2 改写为 1
- 改动要点：所有异常路径（错误子命令、错误编号、空任务）统一 exit 1；无参数裸跑固定 exit 0

### 反3：无单元测试限制亮点分 → **成立，采纳其补强措施，列入改动要点**
- 判定：成立。历史最高 92 分，"可验证性证据缺失"是普遍瓶颈；内置自检是零依赖下的最优解
- 改动要点：todo.py 内置 `--demo` 自检子命令——在**独立临时文件**（如 `.demo_tmp.json`）上跑 add→list→done→rm 全链路断言，输出 PASS/FAIL，结束自清理，不污染真实 todo.json
