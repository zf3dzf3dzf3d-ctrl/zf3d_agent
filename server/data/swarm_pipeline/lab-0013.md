### 文件1：`workspace/todo.py`（新建或就地覆盖）——核心改动
做法：
1. **仅用标准库**：argparse、json、pathlib、sys；硬性禁止 import 任何网络模块（socket / urllib / http / requests 等），禁止 subprocess、os.system。
2. **密闭性锚定**：以脚本自身所在目录为唯一根（取 `todo.py` 的绝对路径父目录）；数据文件固定为同目录下 `todo_data.json`；所有读写路径先规范化再校验必须位于该目录之下，越界立即报错退出（退出码 2）。
3. **子命令集**：add <内容> / list / done <id> / rm <id> / clear。
4. **裸运行保障（任务硬指标）**：`python todo.py` 无参数时打印简明帮助 + 使用示例，以退出码 0 结束。此为历轮分数波动（86↔92）最可能的分水岭，必须守住。
5. **容错**：数据文件不存在 → 按空列表处理；JSON 损坏 → 先备份为 `.bak` 再以空列表继续并提示；操作不存在的 id → 友好报错、退出码 1。
6. **list 输出**：编号 + 完成状态 + 内容；done/rm 操作后回显变更结果。
7. 文件头注释写明约束声明（仅操作本目录、不联网），便于审核对齐。

### 文件2（可选，仅当第0步发现已有测试文件或需要自证）：`workspace/test_todo.py`
做法：标准库 unittest 冒烟用例（add→list→done→rm），数据文件指向临时文件、测试后清理，保证 `python test_todo.py` 一键可跑。

### 红线（不做清单）
- 不触碰 workspace 外任何路径；不发起任何网络请求；不引入第三方依赖；不删除/覆盖勘察中发现的无关文件。

### 验收序列（施工队完成后自测，只运行不改码）
1. `python todo.py` → 打印帮助，退出码 0
2. `python todo.py add 测试事项` → 返回新编号
3. `python todo.py list` → 可见该条
4. `python todo.py done 1` → 标记完成
5. `python todo.py rm 1` → 删除成功
6. 确认 workspace 内仅新增/修改 `todo.py`（及可选 `test_todo.py`）与运行期生成的 `todo_data.json`，无任何外部副作用
