## 三、【实现方法】
- 工具：replace_text 精确替换（自动 .bak）、node `new Function` 语法校验、index.html 缓存号升级、Ctrl+F5 实测。
- S1 关键：警告状态记在前端内存 map（key=对话id+全局projId），「首次」= 该对话内第一次出现该不一致组合。
- S3 关键：只改拼接层文本格式，不动数据源；「近期工作记忆」在注入前做长度截断（保头保尾）。
- S4 关键：缓存兜底策略——快照缺失/异常时回退全量注入（宁多勿缺）；不与 agent-01 前缀缓存优化冲突（该优化管历史消息，本项管最新消息）。
- 坑：该文件可能存在并行会话改动（此前 agent-02-loop-core.js 有 M 状态先例），动手前先 `git status` 确认该文件干净，行号以实读为准不用记忆行号。

## 四、【愿景】

## 五、【风险与备选】
- 风险1：AI 后轮「忘记」项目路径/模式 → 兜底：关键值变化必注 diff + 缓存异常回退全量；工具 cwd 本身有默认值。
- 风险2：并行会话同时改 chatbox 文件冲突 → 开工前 git status 锁基线；改动小步提交。
- 风险3：前缀缓存失效导致 API 成本反升 → 增量注入只动「尾部最后一条消息」，不影响历史前缀缓存（agent-01 机制保护历史段）。
