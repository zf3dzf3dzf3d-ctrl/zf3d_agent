## 一、需求拆解（用户原始诉求）

> "进化树的自动焦点到对话框，和无人监管自动生成和聚焦能做到吗？帮我策划策划，也就是项目工作的可视化这一块。"

拆成三个子问题：

1. **自动聚焦到对话框**：在进化树上点一个节点/能力，能否让对应的工作指令**自动出现在主界面对话框并聚焦光标**，而不是现在"复制→手动粘贴到新对话"。
2. **无人监管自动生成**：项目工作（每个对话任务收尾）能否在**无人点击**的情况下自动沉淀成进化树的候选能力节点、自动生长。
3. **项目工作可视化**：以上两点本质都是"把项目工作过程，用一棵会自己长、会自己提醒、能一键开工的进化树呈现出来"。

**可行性预判（先给结论）**：① 能做，且只差一步前端接线；② 数据层其实**已经默默在跑**，只是前台没人提醒；③ 进化树正是这个可视化的天然载体。下文逐条给实测证据。

## 三、方案设计（分级落地，按改动面/风险从小到大）

### 🟢 P0 · 一键聚焦对话框（纯前端，最小可用，强烈建议先做）

**目标**：进化树上选中节点 →"送入对话框"→ 主界面输入框自动出现指令、光标聚焦，用户回车即开工。

**改动点（2 处，均前端）**
1. `viewer.html` `aiModify()`：在现有"📋 复制指令"按钮旁，**新增**一个"🎯 送入对话框"按钮。
   ```js
   // 复用已有 cmd 字符串（L720-729 已生成）
   parent.postMessage({__tree:1, type:'zfFillChat', text:cmd, autoSend:false}, '*');
   ```
   - 内嵌态（IS_EMBED）走 parent；独立打开态退化为提示"请在画布内嵌视图使用"或 `window.opener` 通知。
   - **默认 `autoSend=false`**，只填不发送，用户保留最终确认权。
2. 主界面（画布容器初始化处）新增监听器（仿 workbench message 模板）：
   ```js
   window.addEventListener('message', e => {
     const d = e.data || {};
     if (d.__tree && d.type === 'zfFillChat') {
       const inputEl = /* 当前活跃对话框输入框，复用 agent-00-send-status.js:457 句柄 */;
       if (inputEl) { inputEl.value = d.text; inputEl.focus();
         if (d.autoSend) /* 触发发送 */; }
     }
   });
   ```

**验收**：点节点"送入对话框"→ 主对话框输入框自动出现完整指令、光标已聚焦；回车才开工；不污染其它会话。
**工作量**：约 0.5 天。**风险**：低（只读注入文本，不自动发送）。

---

### 🟡 P1 · 涌现候选前台可视化 + 角标提醒（前端为主 + 一点后端查询）

**目标**：把 2.2 里"已经在默默生成"的候选**露出来**——任务收尾自动攒出候选后，前台不点任何地方也能看到提醒。

**改动点**
1. 主界面"进化树入口"/工作台顶栏加**角标**：轮询或长连 `capability_tree(action=emerge_pending)`，取 `notified=0` 条数，>0 显示 `🌱 涌现 N 待确认`。
2. 点开角标 → 直接打开 viewer 已有的 `emerge_pending` 面板，逐条 confirm/reject；confirm 后可串接 P0 的"送入对话框"让 AI 补全节点细节。
3. **后端补 1 个轻 action**（或复用 confirm 时置位）：面板处理完回写 `notified=1`，避免角标重复提醒。这是 P1 唯一需要动后端的地方。

**验收**：开关 on 且任务攒满阈值后，角标自动 +1；逐条处理完角标回落为 0。
**工作量**：约 1 天。**风险**：低-中（只是把已有队列露出来，不改生长逻辑）。

---

### 🔴 P2 · 无人值守自动生长（最强大也最危险，默认关闭，需安全闸）

**目标**：高置信候选（clarity 经多任务反复命中累加 ≥ 阈值）自动 `confirm`，树在无人点击下自己 sprout→grow→branch→bloom。

**必备安全闸（缺一不可）**
1. **独立开关**：在 `emerge_enabled` 之外再加 `auto_grow_enabled`，**默认 off**。
2. **单次上限**：一轮最多自动 confirm K 条，防刷屏式疯长。
3. **低频节流**：沿用 `_emergence` 攒 N 次的节奏，自动生长更低频（如每日 / 每 M 任务一次批处理）。
4. **全程审计**：所有自动 confirm 写 `emergence_event(detail='auto_grow')`，前台"生长日志"可追溯、可一键回退。
5. **红线（铁律）**：自动生长**只改树（数据/可视化）**，**绝不自动往对话框发活、绝不触发任何真实工具执行**——干活永远由人在 P0/P1 点"送入对话框"后回车决定。

**验收**：开关 on 时树按阈值缓慢长新枝、有审计日志可回退；开关 off 时行为与现状**完全一致**。
**工作量**：约 2-3 天 + 评审。**风险**：高（AI 自我强化认知可能漂移）。必须分级、可回退、有人工兜底，并与既有「可编排后台流水线」策划案的"提交即返回 + 人工审核回路"思路对齐。

## 四、排期与里程碑建议

```
阶段一（立即可做，0 风险）   P0 一键聚焦对话框        ~0.5 天   →  点节点即开工
阶段二（紧随其后，低-中风险） P1 涌现候选角标可视化    ~1 天     →  无感生成变有感提醒
阶段三（按需评审后启动，高风险）P2 无人值守自动生长    ~2-3 天   →  可控自长 + 审计回退
```

**推荐路径**：先交付 P0 + P1（合计约 1.5 天）。这两步做完，用户的原始诉求"自动聚焦 + 无人监管自动生成 + 可视化"在体验上已经**基本达成**——候选会自动攒、前台会自动提醒、一键就能开工。P2 是"锦上添花且带风险"的增强，**建议 P0/P1 上线观察到实际候选质量后再决定是否投入**。

## 五、风险登记与对策

| 编号 | 风险 | 等级 | 对策 |
|---|---|---|---|
| R1 | P0 自动注入误触发发送 | 中 | 默认 `autoSend=false`，只填不发；用户回车才执行 |
| R2 | 跨 iframe 消息被其它来源伪造 | 中 | 监听器校验 `e.data.__tree===1` 且来源 origin 白名单 |
| R3 | 角标轮询过频拖慢主界面 | 低 | 拉长轮询间隔或改长连；emerge_pending 只查 notified=0 轻量计数 |
| R4 | P2 自动 confirm 导致认知漂移/脏节点 | 高 | 默认 off + 单次上限 + 节流 + 审计可回退 + 只动树不派活（铁律） |
| R5 | 候选质量差（提炼名不准） | 中 | 候选先以 sprout/clarity=0.1 低清晰度入库，靠人 confirm 或多次命中累加才升格；P2 只对高 clarity 生效 |
| R6 | 多会话 subject_id 串台 | 低 | 侦测已按 sessionId 隔离（api L1690），角标/面板按当前会话过滤 |

## 六、整体验收标准（策划案对应交付）

- [ ] P0：进化树选中节点→"送入对话框"→主对话框自动出现指令且光标聚焦；默认不自动发送。

- [ ] 全程：任何自动行为均不阻塞 task_complete 主流程（沿用现有 try/except 静默）；不触碰其它会话上下文。
