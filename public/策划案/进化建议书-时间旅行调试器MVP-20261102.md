# 进化建议书：给"时间旅行调试器"一条可直接开工的 MVP 路线

> 2026-11-02 · 进化师 · 基于《策划案-新功能五方向评估-20261102.md》与实读代码。

## 对象
《新功能五方向评估》中的方向3"时间旅行调试器"——评估已判它为唯一真新范式并推荐立项，但**停留在"方向评估"层面，缺一条能直接派工的落地路线**。

## 改什么 / 为什么
建议把方向3细化为三步 MVP，全部锚定已实读代码：

1. **快照层（最小增量）**：在 agent 工具循环（cli.run_once 内每次工具调用前）调用 `git stash create` 生成快照对象（只存对象不污染工作区、不产生 commit），把 `<session_id, 步号, stash sha>` 写入已有 chat 库 agent_turns 旁的一张小表或 JSON。**不改任何现有锁逻辑**。
   - 为什么选 stash create 而非 tag：tag 会进 refs 列表污染仓库；stash create 纯对象，`git stash store` 亦可按需保留。
2. **回滚 API**：新增一个极简工具（复用 worktree 隔离思想）——回滚=对目标 stash 做 diff 反向 apply 到 worktree 先验证，无冲突才落到主区；对话上下文按 agent_turns 截断到该步重开循环。**绝不 `git reset --hard` 主区**（脏工作区归因纪律禁止）。
3. **前端最小交互**：对话气泡菜单加"从此步重试"，调上述 API。

## 预期收益
- 用户可"回档重试"，失败任务不再从零重来；agent_turns 已按 session 存（chat 库），对话分支成本极低。
- 快照链天然是"工作区历史",可与 swarm_pipeline 的 git 实据门禁互补：审核师可直接抽查任意步快照 diff。
- 业界无同类"对话级 git 时间线"一等公民，惊艳度即卖点。

## 风险与边界
- worktree_isolate 当前**默认关**（swarm_pipeline.py:418 实证），且其启用前置条件注释（409-414 行）明确要求"仓库无未提交改动"——MVP 第一步不依赖它开启，只借鉴其失败降级思想：快照失败静默跳过不阻断主流程。
- 高频快照膨胀：每对话只保留最近 N=20 步快照对象，`git stash drop` 定期清理。
- 不做：跨对话回滚、并发分支合并——留 P2 演进。

## 一句话建议
不要让"五方向评估"停在评估；把方向3拆成上面三步（快照层→回滚API→气泡菜单），其中第1步一个会话即可落地验收。
