# 注意力模式·策划案：箭头「全部完成返回」→ 右侧成功提示排队

> 版本 v1.2 ｜ 状态：待评审 ｜ 2026-XX-XX
> 关联文件：`public/js/chatbox-converge-arrow.js`（收口箭头）、`public/js/chatbox-02-success-arrow.js`（查看成功按钮，UI 参照）

---

## 一、背景与问题

现状：多角色探讨 / 蜂群模式下，源对话 ↔ N 个子对话之间有收口箭头。当所有子对话框完成后，箭头显示「全部完成，可返回」状态，但**返回动作必须由用户自己去找到并点击箭头**才能触发，注意力成本高、容易漏看。

目标：让"全部完成可返回"这件事，像右侧成功提示（查看成功 N）一样**主动排队推到用户眼前**——右侧直接出现每个箭头的返回卡片（附各子对话分数），用户点击任意一张卡片 = 立刻完成该箭头的返回回注。用户不用找箭头，点击即达。

---

## 二、核心交互设计

### 2.1 触发条件
收口箭头（ZFConvergeArrow）检测到「该组全部子对话已完成」时（复用现有完成状态判定），不再只把状态写在箭头本体上，而是**注册一条"返回待办"到右侧队列**。

### 2.2 右侧返回卡片队列（新 UI）
- 位置：屏幕右侧中部，纵向堆叠，与现有「查看成功」按钮区域不重叠（建议在其上方 60~80px 处，或作为同一容器的兄弟节点）。
- 每张卡片显示：
  - 箭头/角色图标 + 源对话标题（如「🧭 多角色探讨：XXX」）
  - 全部完成徽标「✅ 全部完成」
  - **每个子对话一行：视角名 + 分数**（如「技术可行性 88」「成本效率 76」），分数来源见 2.4
  - 卡片右侧一个大号「⬅ 返回」按钮
- 卡片布局：主体（标题+徽标+成员分数列表）+ 右侧两个操作区：一个大号「⬅ 回收」按钮；卡片整体支持单击/双击手势。
- 手势与按钮（三者并存，按用户口径）：
  - **单击卡片主体** → 关闭（移除）该卡片，不触发回收（纯 dismiss，不误触返回）。
  - **双击卡片主体** → 摄像机跳转直达该收口箭头；若箭头已处于「全部完成·就绪」状态，则双击第二击直接触发回收回注（复用箭头回收函数入口）。
  - **「⬅ 回收」按钮** → 直接点击即回收（与点击箭头本体完全等价），卡片播放成功微动画后移除。
  - 单/双击判定用 300ms 定时器：单击延迟 300ms 执行 dismiss，期间收到第二击则取消 dismiss 改为双击直达/回收。
- 成员分数：卡片主体显示每个小队成员（子对话）一行：视角名 + 分数（如「技术可行性 88」「成本效率 76」），缺分显示「—」。
- 自动消失：卡片永不自动消失（与 toast 不同），防止用户错过；仅两种方式移除——①用户点了返回 ②该组对话被删除。

### 2.3 分数提取
- 子对话完成时，从其最终答案中提取分数/评分（正则匹配「XX分」「评分：XX」等模式，与现有审核员分数口径对齐；如项目已有统一分数解析函数则复用）。
- 提取不到分数时显示「—」占位，不阻塞卡片出现。
- 分数在卡片上实时更新：子对话完成即插入/更新该行，全部完成后卡片进入"可返回"高亮态（描边发光）。

### 2.4 与现有「查看成功」的关系
- 两者互补、互不替代：「查看成功 N」管的是**单个任务成功后的查看**；本队列管的是**多子对话全部完成后的返回回注**。
- 建议共用同一个右侧容器 `zf-right-queue`，未来其他待办（审核待办、总结待办）也可挂进来，形成统一的"右侧注意力队列"。
- 子角色窗（策划师/审核员/总结师/施工队）成功不计入本队列，口径与 `_getUnreviewedSuccesses` 的排除规则一致。

### 2.5 提示语音（应用内）
- **语音提醒**：卡片入队（全部完成可返回）时，播放语音提示「任务全部完成，可以返回」——优先用浏览器 SpeechSynthesis（`speechSynthesis.speak`，中文语音，无需音频文件）；备选方案为预置提示音效文件。
- **提示音分级**：
  - 子对话逐个完成：轻提示音（短"叮"，可静音），对应卡片上成员分数实时更新。
  - 全部完成、卡片入队：语音播报 + 高亮音效，确保用户分心时也能感知。
- **频控与静音**：同一时刻多组完成只播报一次并附数量（「3 组任务全部完成」）；设置中提供「语音开/关」开关（存 localStorage），默认开启、音量适中，不打断正在播放的 TTS（排队播放）。

### 2.6 程序关闭后的 Windows 系统通知
- **场景**：用户把程序窗口最小化/关闭到托盘（或切到别的窗口）后，子对话组全部完成时，应用内右侧队列用户看不到 → 需要Windows 系统级通知兜底，样式与现有「任务成功」通知一致。
- **实现（两条通道，按程序状态自动选择）**：
  1. **Web Notification API（窗口在后台但进程存活）**：卡片入队同时调用 `new Notification('✅ 全部完成，可返回', { body: '多角色探讨：XXX\n技术可行性 88｜成本效率 76', icon: ... })`，点击通知 → 聚焦程序窗口并触发对应卡片回收（与点「⬅ 回收」等价）。首次使用前 `Notification.requestPermission()`。
  2. **Windows Toast / 托盘气泡（Electron/客户端壳 或 程序窗口已关闭）**：若项目为 Electron 壳，用 `new Notification()`（Electron 主进程）走 Windows 通知中心，点击同样回聚焦并回收；若窗口完全关闭但需提醒，则由后台服务端检测到全部完成事件后通过 Windows 本地弹窗（powershell BurntToast / msg 弹窗）弹出，样式与「任务成功」通知一致。
- **通知内容**：标题「✅ 任务全部完成」；正文含源对话标题 + 各成员分数摘要；点击直达回收。
- **去重**：同一组只发一次系统通知（与卡片去重共用 srcId 键）；用户在应用内已点回收后再发出的通知自动撤回/忽略。

1. **状态上报**：在 `chatbox-converge-arrow.js` 完成状态变更处，调用新模块 `ZFRightQueue.pushReturnCard({srcId, title, members:[{name, score}], arrowRef})`。
2. **分数监听**：在子对话消息完成处（task-status 变更），调用 `ZFRightQueue.updateMember(srcId, boxId, {score, done})`。
3. **返回执行**：卡片按钮 click → 直接调用箭头本体同款回收函数（找到该 srcId 对应的收口箭头 DOM，触发其 click 或调用其内部回收方法），保证行为 100% 一致，不另写回注逻辑。
4. **持久化**：队列状态存 localStorage（key 如 `zf_right_return_queue`），刷新后按存活对话恢复；源对话已删除的卡片静默丢弃（参照 regApply 的 aliveIds 过滤）。
5. **语音模块**：`ZFRightQueue.speak(text)` 基于 `speechSynthesis`，封装频控/静音开关（localStorage `zf_right_queue_voice`）；卡片入队处调用。
6. **系统通知模块**：`ZFRightQueue.notifySystem({title, body, srcId})`——进程存活时走 Web Notification；Electron 壳存在时优先走主进程 Toast；窗口关闭场景由服务端（全部完成事件落库后）触发 Windows 本地通知（powershell BurntToast 或 msg）。通知点击回调统一走"聚焦窗口 → 触发回收"同一条链路。
7. **新文件**：`public/js/chatbox-right-queue.js` + `public/css/right-queue.css`，不动现有箭头逻辑主干，纯增量接入。

## 四、验收标准

1. N 个子对话全部完成后，右侧 1 秒内出现对应返回卡片，含全部小队成员分数（缺分显示 —）。
2. 点击卡片「⬅ 回收」按钮效果与点击箭头本体完全一致；点击后卡片移除、箭头进入回收完成态。
3. 单击卡片主体 = 关闭卡片（不回收）；双击卡片主体 = 摄像机直达箭头，若箭头已就绪则直接回收。
4. 多组任务并发完成时卡片纵向排队，互不干扰；刷新页面后未处理的卡片恢复显示。
5. 单任务成功（非多角色场景）不产生本卡片，避免与「查看成功」重复打扰。
6. 子角色窗排除规则生效，中间环节完成不入队。
7. 卡片入队时播放语音提示「任务全部完成，可以返回」，语音开关生效；多组同时完成只播报一次。
8. 程序最小化/切走窗口时，Windows 弹出系统通知（样式与「任务成功」一致），点击通知聚焦窗口并完成回收；同一组不重复发通知。
