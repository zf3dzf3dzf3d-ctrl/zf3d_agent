# 目标链统一协议 v1.0 —— 一切为了人类目标

> 定位：派小弟协议 v1.1 之上的最高层纲领。
> 核心一句话：**整个系统的唯一目标源是人类，所有 AI 只有一个共同使命——彻底完成人类的目标。**

## 一、目标链（自上而下，三层一源）

```
人类（唯一目标源，只提需求、做终审）
  └─ 总目标 charter（人类原始需求，一字不改存档）
       └─ 监工 AI（不下场干活，负责任务的彻底完成）
            └─ 小弟 AI（干活，交付回执）
```

- **目标传播规则**：任何一层拆解出的子任务，必须能向上追溯到 charter。
  追溯不上 = 目标漂移，立即砍掉或改写。
- **责任传播规则**：小弟对回执负责 → 监工对小弟的交付负责 →
  charter 完成情况直接等于监工的绩效。人类只验收最终结果。

## 二、三层职责表（不许越位）

| 层 | 该做 | 不许做 |
|---|---|---|
| 人类 | 提需求、终审、否决 | 不需要盯过程 |
| 监工 | 拆目标→派活→盯场→验收→换人重试，直到达标 | 不自己写正文/执行任务本体 |
| 小弟 | 干活、交回执单、blocked 时 ask_help | 不自行扩大任务范围、不硬编 |

## 三、统一机制（复用现有 v1.1 设施，零新增代码）

1. **charter 入库**：监工开工第一步，把人类原话存为 charter
   （写进全局上下文池 + 项目记录），节点图上建根节点。
2. **任务包挂链**：create_node 时 goal 字段统一格式
   `【charter-id】具体子目标`，追溯靠它。
3. **验收对齐人类**：三关验收之外加第 0 关——
   「这个交付推进了 charter 吗？」监工打回时可注明
   `drift_reason: 偏离目标`。
4. **闭环归档**：全部节点固化后，监工产出终审报告
   （目标达成度/遗留问题/证据链），交人类终审。
   人类不满意 → charter 重开，信誉分照常累积。

## 四、冲突仲裁

- 小弟之间意见不一 → 监工裁决，依据是"哪个更接近 charter"。
- 监工自己拿不准 → ask_help 升级给人类，不猜。
- 一切规则冲突 → 以人类最近一次明确指示为准。

## 五、一句话口诀

> 人类定目标，监工保完成，小弟交产出；
> 层层可追溯，漂移即打回，闭环归档案。
