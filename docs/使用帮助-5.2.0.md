## 一、对话池系统（chat_pool）：断网不掉字

### 解决什么问题？

5.1.5 及以前，一轮对话是「浏览器拖着请求跑」：你的浏览器直接连大模型服务器，Wi-Fi 瞬断、切换网络、刷新页面，上游请求就被杀死——回复丢一半，还会触发重试风暴把整轮重新发一遍（费钱费时）。老毛病：USB 无线网卡的 ERR_NETWORK_CHANGED 断流。

### 5.2.0 的工作方式

- 对话 = 服务器内存池中的**常驻槽位**（游戏对象池思想：槽位可擦除、可复用、池本身常驻）
- 上游大模型的回复**先落入服务器槽位的事件缓冲区**，前端随时来读
- 断线后重连，带上游标（cursor）**从断点续读，一个字不丢**
- 排队等待在服务器 worker 里进行，不占浏览器连接

### 使用上有什么变化？

| 场景 | 5.1.5 | 5.2.0 |
|---|---|---|
| Wi-Fi 瞬断 | 回复丢失，可能整轮重发 | 重连后断点续读，零丢失 |
| 刷新页面 | 正在生成的回复没了 | 秒恢复，接着看 |
| 点停止 | 取消请求 | 取消生效且闸门正常放行 |
| 守卫/风筝监控 | 正常 | 照常工作，零改动 |

> 💡 无需任何配置，升级后自动生效。想保守一点可只开缓冲区不开连接池（见 server 配置 chat_pool.conn_pool.enabled）。

## 二、对话交通系统 chat_gate v4

所有大模型请求经过唯一闸门统一调度：

- **按接口域名分车道组**：不同供应商互不排队
- **AIMD 自适应调度**：拥塞时自动收，畅通时自动放
- **车道数自适应伸缩**：忙时多开车道，闲时收回

**分工铁律**：闸门=交警（决定谁先走），池=车队+仓库（决定用什么走、货在哪）。池对守卫/风筝只提供只读快照，单向旁观、零耦合。

排队的可视化不变：闸门面板照常能看到每张票据的排队/运行状态（含 entry='pool' 标记的池路径票据）。

## 三、连接池：更快的请求

按 API 域名分组的 HTTPS 长连接复用：

- 每个请求省去 TCP+TLS 握手，**快 50~200ms**
- 「重生式常驻」：被供应商掐了空闲连接，请求阶段报错即弃旧建新，自动重试一次
- 支持 Clash 等系统代理环境

## 四、前缀缓存观测：省钱看得见

服务端解析上游 usage 里的 cached_tokens：

- 缓存**命中率**变成可见数字
- 每次对话**省了多少钱**可统计
- 为后续「前缀纪律」优化（让提示词结构更利于缓存命中）打地基

在 token 用量面板（panel-token-usage）可查看相关统计。

## 五、小狗守卫 v5.2：工具停滞检测

### 新规矩：只管真正卡住的

- 只有「闸门里真实 running、但工具超过阈值没动静」的票据才触发提醒，默认阈值 **30 分钟**（环境变量 WATCHDOG_STALL_SECONDS 可调）
- 同一张票据的停滞提醒**自动去重**，不会反复轰炸

### 忙时免打扰（v4.5.1 延续加强）

闸门有活跃票据（排队/运行中）时，守卫**不注入通知**，避免插队打扰正常任务；崩溃报告保留到下轮巡检再投递，不会丢。

### 其他改进

- watchdog 日志自动轮转（上限 512KB），不会撑爆磁盘
- 崩溃时自动抓取 stdout traceback 上下文，保存崩溃报告并请 AI 分析原因
- 软件挂掉 5 分钟内自动拉起（watchdog 独立进程守护）

## 六、热更新引擎（hot_reload）

给开发者和高级用户：

- **服务端模块热重载**：改 Python 模块不用重启整台服务器，修改即生效
- **全局状态跨重载保留**：定时任务注册表和锁在重载后不丢
- **前端变更通知**：静态文件（JS/CSS）变更后自动广播，前端提示刷新
- 支持手动触发指定模块重载或全量重载
