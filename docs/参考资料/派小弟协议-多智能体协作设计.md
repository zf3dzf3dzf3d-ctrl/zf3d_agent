# 派小弟协议（多智能体派发-回收-验证标准流程）v1.0

> 目标：把「主脑 AI 派活给节点图上的小弟（子智能体）」流程化、可视化、可复用。
> 载体：现有无限画布节点图（create_node / run_node / read_node / 全局上下文池）+ 守护进程监工。

## 一、总览：四段流水线

```
[派发] → [监控] → [回收] → [验证]
 标准任务包   心跳事件    回执单     三关验收
```

## 二、派发：标准任务包（Task Packet）

主脑派活不发自然语言，只发结构化任务包（存入节点属性 + 全局上下文池）：

| 字段 | 说明 |
|---|---|
| id | `sub-<节点id>-<序号>` 唯一编号，回收对账凭据 |
| goal | 一句话目标 |
| accept | **可检查的验收标准（必填，无标准不发）** |
| deliverable | 产出物清单（文件路径/结论摘要） |
| constraints | 超时秒数、禁止事项、预算 |
| report_format | 回执模板（见第四节） |

映射到画布：一个任务包 = 一个节点。create_node 时把上述字段写入节点属性，节点标题 = goal。

## 三、监控：事件驱动，不轮询

- 小弟每完成一个子步骤，向全局上下文池写状态：`{step, status, 产出, 时间}`
- 事件类型：
  - `waiting` → 小弟需要主脑补充信息（主脑收到通知后注入）
  - `failed` → 立即介入，注入修复方法或 delete_node 重建
  - `timeout` → 守护进程已暂停该节点并注入修改方法（沿用现有"运行超时守护"）
  - `heartbeat` → 正常推进的心跳
- 可视化：节点状态直接映射节点图样式（进行中=呼吸光晕、等待=黄色描边、失败=红色、完成=绿色✓、固化=锁定图标）

## 四、回收：统一回执单（Receipt）

小弟完成必须交回执（task_complete 强制模板），含：
1. 生命周期状态：done / failed / blocked
2. 产出物清单：文件路径 + 内容摘要
3. 自述：做了什么、改了哪些文件、遗留问题
4. 证据：实际跑过的验证（命令输出、测试结果）——不接受"应该没问题"

## 五、验证：主脑三关验收（不信自述，只信证据）

1. **存在性**：file_info 检查产出文件真实存在
2. **正确性**：py_compile / node --check / 冒烟测试实跑
3. **无副作用**：git status / diff 检查未改到不该改的文件

三关全过 → set_node_fixed 固化节点，结论写入全局上下文池供下游节点复用。
任一关不过 → 打回重做（run_node 重跑）或 delete_node 软删重建。

## 六、与现有系统的映射

| 协议角色 | 现有实现 |
|---|---|
| 派发 | create_node（节点属性存任务包） |
| 执行 | run_node（前置依赖校验 + 下游接力） |
| 状态信箱 | 全局上下文池 + read_node / read_global_context |
| 监工 | 守护进程（超时暂停+注入、空闲注入、日常巡逻） |
| 回收入口 | 节点 task_complete 回执模板 |
| 验收 | 主脑实跑验证命令 + git diff |
| 归档 | set_node_fixed 固化 + read_tool_store 复用历史结果 |

## 七、补充机制（v1.1）

### 7.1 小弟反向求助（blocked 状态）
小弟干到一半发现前置条件不满足（缺文件、任务包验收标准矛盾等），发标准求助帧而非硬编结果：
`{type: blocked, 卡点描述, 需要主脑补充什么}`，复用 waiting 通道通知主脑注入。

### 7.2 信誉档案
每次验收通过/失败，往项目记录写一条小弟档案（任务 id、耗时、一次通过率）。
积累数据后主脑派活可参考：任务类型该派给谁、timeout 该设多长。

### 7.3 死锁与环路防护
A 等 B、B 等 A 的环形等待在节点图自动连线时可能出现。派发前（create_node 建依赖边时）
做一次 DFS 环路检测，有环直接拒绝并提示主脑拆环。

### 7.4 小弟热替换（reassign）
主脑可随时把任务从小弟 A 转给小弟 B，触发条件：failed 两次 / timeout / blocked 超时未响应 /
主脑主动判断 A 干不动。流程：
1. 旧节点标记 `reassigned`（保留 A 的历史产出到工具仓库供 B 参考，不软删——留痕可追责）
2. 新建节点继承原任务包（id 不变，加 `-r2` 后缀表示第 2 任），constraints 追加
   「前人卡点：<A 的最后状态摘要>」，避免 B 重踩同样的坑
3. 每个任务包记录 `assigned_to` 与 `attempt` 次数；同一任务 attempt ≥ 3 次升级回主脑亲自做
4. 信誉档案同步：被替换的小弟记一条 replaced，主动替换不计入失败

## 八、下次调用的标准话术

主脑只需说：「按派小弟协议派发：goal=xxx，accept=xxx，deliverable=xxx，timeout=xxx」，
即自动走完派发→监控→回收→验证全流程。
