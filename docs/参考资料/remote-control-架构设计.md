# 多机互联远程控制系统 · 架构设计 v1

> 目标：朱峰社区智能体无限 5.1.0 每台电脑的实例拥有唯一界面 ID；控制端输入对方 ID、对方同意后，即可远程查看并同步操作对方界面；一个控制端可随时切换控制不同电脑的实例。

## 一、总体拓扑

```
电脑A(控制端)                远程服务器(信令+中转)                电脑B(被控端)
┌──────────┐   wss    ┌──────────────────┐    wss   ┌──────────┐
│ 朱峰实例  │ ◄──────► │ 5.1.0 server 新增 │ ◄──────► │ 朱峰实例  │
│ +控制面板 │          │ /ws/remote 通道    │          │ +被控模块 │
└──────────┘          │ ID注册表/会话管理  │          └──────────┘
                      └──────────────────┘
```

选型：**WebSocket 服务器中转**（不用 WebRTC）。
理由：
- 项目已是纯 Python 标准库 HTTP 服务（ThreadingHTTPServer），无第三方依赖原则；
- 同一前端是浏览器页面，界面同步本质是"应用状态同步"而非视频流，数据量小，中转延迟足够低；
- WebRTC 需要 STUN/TURN 与 SDP 交换，复杂度高且内网穿透不稳定；
- 用户场景是"控制自己的另一台电脑的实例"，服务器中转最简单可靠。

## 二、唯一 ID 体系（加密配对码版）

**原则：ID 是隐私凭证，不明文展示、不明文传输。**

**盲配对原则（本地是"盲人"）：** 任何一方无法主动浏览、发现、枚举其他主机——服务器不提供任何"在线设备列表"接口；两端彼此不可见，只有被控端主动把配对码（暗号）通过私聊渠道发给控制端、控制端在 30 秒内输入配对成功，才进入授权流程。没有暗号，双方在服务器上互为匿名影子。

### 2.1 身份与密钥

- 每个实例首次启动生成：
  - `device_key`：32 字节随机主密钥（永不出本机，存 `private/remote_id.json`，权限 600）；
  - `device_id_hash`：SHA-256(device_key) 前 16 字节，**这是对外唯一标识**（单向哈希，泄露也无法反推或伪造身份）；
- 服务器注册表只存 `device_id_hash` → 连接句柄，**永远拿不到原始 ID 和密钥**。

### 2.2 配对码（加密的"临时 ID"）

不想记哈希？被控端可主动生成**临时配对码**：

- 格式 `ZFA-XXXXX-XXXXX`（10 位，base32，含校验位）；
- **配对码有效期 30 秒**（超短时效，过期即作废，双方界面都有倒计时提示）；
- 生成时才在界面显示（点击「远程」→「生成配对码」才出现，平时不可见，防止旁观偷拍）；
- 控制端输入配对码 → 服务器用码中加密载荷定位被控端并发起授权请求——**全程原始 device_key 不离开任何一台机器**；
- 中间人抓到配对码也没用：一次性 + 30 秒时效 + 不知道密钥无法伪造后续会话 token；
- 配对成功仍需被控端弹窗点「同意」并选授权时长，双重确认后才进入可操作状态。

### 2.3 会话层安全

- 授权通过后双方用 ECDH（P-256）协商会话密钥，所有 DOM 快照/事件流 AES-GCM 端到端加密——**服务器只转发密文**，无法看到被控界面内容；
- 会话 token 与设备绑定 + 心跳续期，断线即焚；**每个授权会话携带 expires_at 时间戳，服务端心跳校验，过期自动销毁会话与密钥（硬限制，双端无法绕过）**。

### 2.4 防 ID 枚举

- 服务器对错误配对码/未知 ID 的请求统一返回"不存在"，不区分错误类型，杜绝枚举探测；
- 同一来源高频请求触发限流；
- 连接请求必须携带 device_key 签名的挑战应答（防伪造来源）。

## 三、信令与授权流程

```
控制端                      服务器                     被控端
  │── connect(id, token) ──►│                            │
  │◄─ pending ───────────────│── invite(控制端信息) ────►│
  │                          │      被控端弹窗「A请求控制你的界面」
  │                          │◄───── accept / reject ─────│
  │◄─ session_established ───│                            │
  │═════════ 双向数据通道 ════│════════════════════════════│
```

- **授权有效期：可设定时长，到期自动终止**。被控端同意时选择有效期：`1 小时 / 8 小时 / 1 天 / 7 天 / 自定义（上限 30 天）`；到期后服务端会话自动销毁、密钥作废，控制端界面立即断开并提示"授权已过期"。禁止永久授权。
- 会话剩余时长实时显示在双方界面上；被控端可随时点「断开」立即终止，不受时长限制；控制端也可主动放弃。断线即失效。
- 控制端可同时挂多个被控 ID，但同一时刻只有一个 active；切换 = 切 active，无需重新授权（但每个会话各自受自身有效期约束）。

## 四、界面同步方式（关键设计）

被控端不是投屏像素，而是**应用状态同步**（体验更好、带宽极低）：

1. **DOM 快照 + 事件桥**：被控端把主界面（对话区+画布）关键 DOM 结构 serialize 成快照发给控制端渲染成"影子界面"；
2. **事件同步**：控制端在影子界面上点击/输入 → 转成事件描述 `{type:'click',target:'#id',...}` → 被控端 dispatch 同源事件到真实 DOM；
3. **状态回传**：被控端 MutationObserver 监听主界面变化 → 增量 patch 回控制端；
4. 兜底：对复杂区域（画布）可降级为定时截图同步（canvas.toDataURL，1-2fps）。

## 五、安全加固与体验增强（v1.3 补充，2026-09-02 确认）

1. **断线降级**：心跳丢失 10 秒→控制端标灰"连接中断"；60 秒无恢复→会话挂起（密钥暂存但暂停同步）；恢复后增量续传 DOM 差量，不整页重来。
2. **操作审计日志**：被控端本地记录所有远程操作（谁/何时/做了什么），存本机 `private/`，不上传服务器——安全兜底与事后取证。
3. **敏感操作二次确认**：远程触发批量删文件、修改 `api_keys.json`、关闭服务等危险区操作时，被控端弹一次本机确认框。
4. **版本兼容检查**：握手时交换版本号，差异过大直接拒绝连接并提示升级（防新旧版本 DOM 结构不匹配渲染错乱）。
5. **服务器并发限制**：中转只转发信令+加密事件流；单服务器 50 并发会话上限，超出提示（初期够用，不做负载均衡）。
6. **传输量控制**：Canvas 区域 1-2 秒/帧低频截图兜底；文本输入差量合并，避免逐字发送。

## 五（二）、盲配对与防滥用补充（v1.5，2026-09-02）

1. **配对码双向确认防钓鱼**：控制端输入暗号后，双端屏幕同时显示 4 位"比对码"，双方口头/电话核对一致才继续——防中间人假扮（类似银行转账核对收款人）。
2. **暗号显示即计时销毁 + 唯一有效**：30 秒倒计时结束自动从界面消失并作废；同一时刻只允许一个有效暗号，生成新码自动作废旧码，防止截屏旧码被复用。
3. **暗号错误熔断**：输错 3 次 → 10 分钟内禁止该来源再发起配对请求，本地记录来源哈希——让暴力猜码概率归零。
4. **被控端"控制中"常驻横幅**：一旦被控，界面顶部醒目横幅"正在被 XX 控制 + 剩余时间 + 立即断开按钮"，绝不允许无声无息被控制；双方操作冲突时以被控端本机操作优先。
5. **会话密钥定期轮换**：ECDH 会话密钥每 10 分钟自动重协商，单段密文被破译也拿不到后续流量。
6. **中转服务器匿名化**：服务器日志只记哈希与时间戳，不落任何明文；全程 HTTPS/WSS。
7. **紧急熔断键**：被控端检测到异常高频操作（1 秒内 50+ 事件）自动断开并提示——防控制端被劫持后搞破坏。

## 六、安全

- 每实例有 secret，控制请求需 token 校验；
- 被控端明确同意 + 随时断开 + 断线自动失效；
- 服务器记录连接/操作审计日志（复用现有日志体系）；
- 建议公网部署时套 wss（反向代理 TLS）。

## 七、风险与取舍

- DOM 快照对动态组件（canvas 画布）覆盖不全 → 已备截图降级路径；
- 中转延迟 ~几十 ms，操作类场景可接受；
- 两实例同机联调（不同端口）→ 步骤 7 验证方案。
