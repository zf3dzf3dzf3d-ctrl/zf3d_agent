# 知乎专栏版：我开源了一个能同时跑 400+ 个 AI 对话的本地智能体工作台

> 知乎读者吃"故事+观点"，这版把技术干货改成了叙事开头，结尾抛问题引导评论互动。

## 为什么所有 AI 应用都长一个样

不知道你有没有注意到：从 ChatGPT 到各家套壳，几乎所有 AI 应用的交互都是——**一个对话框**。

这个设计的隐含假设是：AI 是一个"聊天对象"。

但用了半年多之后我越来越确信：LLM 更适合被当成**一群干活的员工**，而不是聊天对象。员工不需要你盯着手把手教，你布置任务、验收结果就行了。

于是我自己写了一个：「朱峰社区智能体无限（Infinity）」——Windows 本地优先的 AI 智能体工作台，今天开源了（MIT）。

## 它能干什么

**一句话：一块无限画布 + 一群真的会把事情做完的 AI。**

- **400+ 并发对话**：每个对话是独立智能体，有自己的模型、工具、上下文，还能互相派活、互相监督。曾经让它写文章的智能体把写代码的智能体骂了一顿（因为链接都是坏的），然后那边的智能体默默重写了一遍——多智能体协作的真实一幕。
- **83 个内置工具**：读写文件、跑代码、Git 提交、抓网页、定时任务、文生图、视频生成。
- **无限画布节点图**：在画布上连线跑流水线，每个节点是一个会自己干活的 AI。
- **自我修复**：报错不甩锅，自己读代码定位根因打补丁。
- **超长计划**：跨对话的大任务持久化，换个对话接着干。
- **零依赖**：后端纯 Python 标准库，解压双击就跑。不装 pip 包，不装 Node，不用 Docker。

## 一个固执的技术选择

有人问我为什么不用 FastAPI / Express / Electron， ecosystem 现成的不好吗？

因为**安装摩擦会杀死一切传播**。工具再牛，让用户装 30 个依赖，90% 的人第二步就走了。我宁可自己手写 HTTP keep-alive、路由、数据库、任务调度，也要让用户**解压双击就能用**。

代价是踩坑都是自己的。比如 keep-alive 连接上请求体没排干，残留字节被当成下一个请求的请求行，直接 501——这种 bug 网上搜不到答案，只能自己啃源码。
