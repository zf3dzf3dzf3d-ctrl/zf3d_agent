# CSDN 版：我做了个能同时跑 400+ 个 AI 对话的本地智能体工作台（纯 Python 标准库）

> 首发：掘金。本文为 CSDN 微调版：标题更关键词化、开头加摘要、适合技术社区索引。

**摘要**：一个 Windows 本地优先的 AI 智能体工作台，支持 400+ 并发对话、83 个内置工具、无限画布多智能体协作、自我修复，后端纯 Python 标准库零依赖，解压双击即可运行。开源免费（MIT）。

## 一、痛点：AI 聊天应用都差在哪

现在大多数 AI 应用都围绕"一个对话框"设计。想并行跑 10 个任务？开 10 个标签页，一个个人肉盯着，再互相复制粘贴上下文——这是大部分人的日常。

我想要的是：**LLM 不是聊天对象，而是一群干活的员工**。于是我写了「朱峰社区智能体无限（Infinity）」。

## 二、它是什么

一句话：**一块无限画布 + 一群真的会把事情做完的 AI**。

核心特性：

1. **400+ 并发 AI 对话**：每个对话都是独立智能体（独立模型/工具/上下文），智能体之间互相派活、互相监督、汇总结果。
2. **83 个内置工具（4 大类）**：日常/编程/写作/画布。读写文件、跑代码、抓网页、Git 提交、定时任务、文生图、视频生成，开箱即用。
3. **无限画布多智能体节点图**：画布上创建节点、连依赖、跑流水线。每个节点就是一个完整智能体，相当于可视化 DAG 工作流。
4. **自我修复**：报错后自己重读代码、定位根因、打补丁、再验证。测试期间它真的修好了自己前端的一个 bug。
5. **超长计划持久化**：跨对话大任务持久化成可分享计划，新对话无缝续做。
6. **零依赖启动**：后端纯 Python 标准库，不用 pip install，不用 Node，不用 Docker。

## 三、为什么死磕纯 Python 标准库？

因为**安装摩擦会杀死一切传播**。再牛的工具，如果要求先装 Python、再装 30 个依赖、再配 Docker，90% 的人第二步就流失了。

整个服务端（HTTP keep-alive、路由、数据库、任务调度）全部 stdlib 手写。代价是踩了很多坑——比如 keep-alive 连接上请求体没排干，残留字节被当成下一个请求的请求行直接 501。收益是：**解压双击就能用**。

## 四、技术架构速览

- 后端：Python 3.11+，纯标准库 HTTP server，keep-alive，多线程
- 前端：原生 JS（111 个 script 模块化加载），无限画布渲染
- 智能体内核：工具调用循环 + 自检 + 计划持久化（MD 文件）
- 存储：本地 SQLite / kv_store，数据全部在自己电脑上

## 五、适合谁

- 想把 AI 从"聊天玩具"变成"生产力"的人
- 需要数据本地化（不上传任何代码/数据到第三方）的团队和个人
- 想看一个不依赖框架的项目怎么从零搭起来的开发者（整个仓库就是学习材料）
