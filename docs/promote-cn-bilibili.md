# 【B站专栏】我用纯 Python 标准库写了能同时跑 400+ 个 AI 对话的本地智能体工作台，连前端框架都不用

> 开源免费（MIT）。视频演示看我主页动态，仓库地址文末。喜欢硬核本地工具的可以先三连收藏。

## 一、痛点：AI 聊天应用都差在哪

现在大多数 AI 应用都是围绕"**一个对话框**"设计的。想并行跑 10 个任务？开 10 个标签页，一个个人肉盯着，再互相复制粘贴上下文——这是大部分人的日常。

我想要的是另一种东西：**LLM 不是聊天对象，而是一群干活的员工**。于是我写了「朱峰社区智能体无限（Infinity）」——一个 Windows 本地优先的 AI 智能体工作台。

## 二、它是什么

一句话：**一块无限画布 + 一群真的会把事情做完的 AI**。它不只是聊天——会规划、会执行、会自我验证，改坏了东西还会自己修。

核心特性：

### 1. 400+ 并发 AI 对话
每个对话都是独立智能体，有各自的模型、工具和上下文。智能体之间可以互相派活、互相监督、汇总结果。对，不是"多开标签页"，是真·多智能体协作。

### 2. 83 个内置工具（4 大类）
日常任务 / 编程 / 写作 / 画布。读写文件、跑代码、抓网页、Git 提交、定时任务、文生图、视频生成，开箱即用。

### 3. 无限画布多智能体节点图
在画布上创建节点、连依赖、跑流水线、修坏节点、锁定完成的节点。每个节点就是一个完整智能体——相当于可视化的 DAG 工作流，但每个格子都是一个会自己干活的 AI。

### 4. 自我修复
智能体报错后不是甩锅给你，而是重新读代码、定位根因、打补丁、再验证。测试期间我亲眼看着它修好了自己前端的一个真 bug。

### 5. 超长计划持久化
跨多个对话的大任务会持久化成可分享的计划，新对话能无缝接着上一次干到一半的地方继续。

### 6. 零依赖启动
服务端是**纯 Python 标准库**写的。双击就能跑，不用 `pip install`，不用 Node，不用 Docker。

## 三、为什么死磕纯 Python 标准库？

因为**安装摩擦会杀死一切传播**。一个工具哪怕再牛，如果要求用户先装 Python、再装 30 个依赖、再配 Docker，90% 的人第二步就流失了。

所以我把整个服务端（HTTP keep-alive、路由、数据库、任务调度）全部用 stdlib 手写。代价是自己踩了很多坑——比如 keep-alive 连接上请求体没排干，残留字节被当成下一个请求的请求行，直接 501（这个 bug 修的过程可以单开一篇文章）。但收益是：**用户拿到手解压双击就能用**，这对推广太重要了。

## 四、技术架构速览

- **后端**：Python 3.11+，纯标准库 HTTP server，keep-alive，多线程
- **前端**：原生 JS（约 6MB / 111 个 script，模块化加载），无限画布渲染
- **智能体内核**：工具调用循环 + 自检 + 计划持久化（MD 文件）
- **存储**：本地 SQLite / kv_store，一切数据都在你自己的电脑上
