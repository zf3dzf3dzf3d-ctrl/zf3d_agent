# 团队协议 v1 — 自定义团队规范（2026-11-03）

> 一个自定义团队 = 一个 MD 文件。写好这个文件，派出团队面板就多出一排角色卡，可直接选人、写叮嘱、🚀 派出——**不写一行 JS**。
> 文件即导入导出：把 MD 发给别人，对方在面板「📥 导入」粘贴即可合并使用。

---

## 一、文件格式

```markdown
# 团队协议

## 团队
- id: red-blue            （英文小写+连字符，全局唯一，改 id 视为新团队）
- 名称: 红蓝对抗小队
- 作者: 你的名字
- 版本: 1.0
- 简介: 一句话说明团队用途

## 角色
### 红队参谋
- 图标: ⚔️
- 默认数量: 1
- 叮嘱: 攻击前提假设与隐藏风险，每条反驳标注严重度【高/中/低】
- 职责: 【红队参谋任务】你是红队参谋：对当前方案发起攻击性质疑，找前提漏洞、可行性问题、被忽略的反例。讲证据讲逻辑，不为反驳而反驳。
- 结论标签: 【红队参谋结论】

### 蓝队工程师
- 图标: 🛡️
- 默认数量: 1
- 叮嘱: 只出最小化修补方案，每步不超过3个文件
- 职责: 【蓝队工程师任务】你是蓝队工程师：针对红队指出的问题给出最小化修补方案（只出方案不动工），每条方案附文件与行号依据。
- 结论标签: 【蓝队工程师结论】
```

## 二、字段说明

| 级别 | 字段 | 必填 | 说明 |
|---|---|---|---|
| 团队 | `id` | ✅ | 英文/数字/连字符，全局唯一标识（用于叮嘱存储 key、去重合并） |
| 团队 | `名称` | ✅ | 显示名 |
| 团队 | `作者`/`版本`/`简介` | ❌ | 溯源信息 |
| 角色 | `### 角色名` | ✅ | `## 角色` 下每个三级标题 = 一个角色卡 |
| 角色 | `图标` | ❌ | emoji，默认 🎭 |
| 角色 | `默认数量` | ❌ | 面板点开时预选人数，默认 0 |
| 角色 | `叮嘱` | ❌ | 用户没写一句话叮嘱时的默认职责（对应 defBrief） |
| 角色 | `职责` | ✅ | 素材包开头的任务定义（对应 taskHead），写清「你是谁/干什么/铁律/输出格式」 |
| 角色 | `结论标签` | ❌ | 回注原对话时的标记，默认【角色名结论】 |

## 三、引擎约定（协议角色自动获得）

协议角色走引擎现成的 `_objectorExpand(box, chat, cfg)` 通用派出通道，**自动继承**：

1. 素材包：原对话完整上下文 + 项目路径 + 溯源四要素 + 你的「职责」+ 用户一句话叮嘱；
2. 工具权限：允许 read_file/search_in_files/run_code 实地调查；
3. 全自动回收与派发账本登记；
4. 结论统一前缀回注原对话（前缀 = 结论标签）。

**不要在「职责」里重新描述素材包/回收机制**，只写角色本身的专业职责。

## 四、导入导出与合并

- **导出**：面板「📤 导出」把当前所有协议团队拼成一个 MD 复制走；
- **导入**：粘贴 MD → 按 `团队.id` 合并（同 id 覆盖、异 id 新增），天然支持多人团队合并；
- **存储**：localStorage `zf_crew_protocols`（JSON 数组，每项含原始 md，随时可再导出）。

## 五、设计原则

- MD 即协议、即配置、即分享单元——零代码新增团队；
- 引擎只认「cfg 配置对象」，协议加载器只是 MD→cfg 的翻译器，未来格式升级只改翻译器；
- 角色 = 一段专业职责文案 + 一个图标，其余交给引擎，避免重复造轮子。
