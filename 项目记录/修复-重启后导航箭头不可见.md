# 修复：重启后老对话导航箭头不可见

## 问题
重启应用后，重启前的老对话窗口在画布上可见，但左右两侧的会话导航圆圈箭头不显示（变灰、无法点击），系统"不认可"这些对话。

## 根因（两层）
1. **状态丢失**：任务成功/失败状态 `chat._taskStatus` 只存在内存，运行时由 `task_complete` 终止时设置（app-agent.js L1286）。重启后 `restoreSession()`（app.js）只恢复窗口和消息，不恢复该状态 → 所有老对话状态都是 `idle`。
2. **显示条件过严**：`_updateNavArrowStatus()`（app-chatbox.js L617-627）原逻辑是**只有邻居状态为 success 才显示箭头**，否则加 `nav-none` 类（opacity 0.3 + pointer-events none，不可见不可点）。`task_stats` 表的 success 字段全为 0（是 API 调用统计非任务结果），无法用于恢复。

## 修复方案（已实施）
### 1. app.js restoreSession()
- 恢复消息后，扫描持久化消息中的"✅ 任务完成 / ❌ 任务失败"（task_complete 时持久化的总结消息），推断 `chat._taskStatus`。
- 规则：取最后一条结果消息；若其后没有新用户消息，则恢复对应状态（有新用户消息说明是新任务进行中，不恢复旧状态）。
- 末尾追加：`_updateAllNavArrows()` 立即刷新导航箭头 + 每个框 `updateStatusDot()`。

### 2. app-chatbox.js _updateNavArrowStatus()
- 箭头改为**有邻居即显示**，颜色随邻居状态：success=绿 / error=红 / sending=橙 / queued=黄 / 其余=蓝(nav-idle)。
- 只有真正没有邻居（最左/最右）才显示 nav-none。
- 顺带修复原代码右圆圈 else 分支写错类名的笔误。

## 修改文件
- `public/js/app.js`（备份 .bak_navfix）
- `public/js/app-chatbox.js`（备份 .bak_navfix）

## 验证
- `node --check` 两文件语法均通过
- 修改区域读回确认无误

## 效果
重启后所有老对话（cb1~cb12）的导航箭头均可见可点，颜色反映重启前的任务状态；成功过的对话显示绿色箭头。
