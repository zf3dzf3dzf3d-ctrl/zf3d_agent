# 工具集不一致问题修复记录

## 问题描述
用户发现模式2（编程模式）会话实际注入的工具数（21个）与系统定义不符，且提示词中的数字（极简15/编程28/写作40共83个）与实际代码定义（极简16/编程43/写作57）不一致。

## 根因分析（3个独立问题）
1. **提示词数字过期**：`public/prompts/模式2_工具循环/02_可用工具清单.txt` 写的是旧版数据（15/28/40=83）
2. **旧 localStorage 屏蔽新工具**：`tools-settings.js` 的 `initSelected` 从 localStorage 读用户旧保存的工具子集（如仅7个），系统升级新增的工具（generate_description、move_file 等）被永久屏蔽，导致会话注入的工具比分类定义少
3. **server 动态注入丢失元工具**：`handler_routes.py` 服务 tools-definitions.js 时用 minimal/ 文件夹文件列表（15个）完全替换极简分类数组，丢失了无物理文件的元工具 `switch_tool_category`，导致极简模式下 AI 无法调用它切换分类

## 修复内容（3处）
| # | 文件 | 修改 |
|---|---|---|
| 1 | `public/prompts/模式2_工具循环/02_可用工具清单.txt` | 更新为实际数字：极简16/编程43/写作57，去重共84个；补充 move_file/task_list/get_tool_result/generate_description 等缺失工具的描述 |
| 2 | `public/js/tools-settings.js` | `initSelected` 增加"新工具自动补全"逻辑：保存列表中不存在的新工具自动启用，不再被旧数据屏蔽 |
| 3 | `server/handler_routes.py` | 动态注入极简分类时补回 `switch_tool_category` 元工具（insert(0)） |
| 4 | `public/index.html` | tools-settings.js 版本号 v=1 → v=2（缓存刷新） |

## 验证结果（全部通过）
- 提示词数字：16/43/57/84 ✅
- tools-settings.js 语法 OK，模拟测试：旧保存7个工具时修复后极简注入16个、编程注入43个 ✅
- handler_routes.py 语法（py_compile）OK ✅
- 模拟服务端注入后极简分类=16个，含 switch_tool_category + task_complete ✅

## 权衡说明
修复2的副作用：用户明确禁用某工具后保存，下次启动该工具会被自动补全恢复（因无法区分"明确禁用"与"保存时不存在"）。用户如需禁用需再次取消勾选。相比"新工具永久被屏蔽"，此权衡合理。

```

              ↓ server 服务该文件时动态注入极简分类 = minimal/文件夹 + switch_tool_category

```
